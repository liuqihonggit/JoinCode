## 问题清单

### 问题1：[DIAG-GIT] 调试日志硬编码污染输出（高严重度）✅ 已修复

- **位置**: `infrastructure/Infrastructure/IO/Process/GitCommandRunner.cs:25,37,51,57`
- **现象**: 所有 git 相关工具（gh_pr_list, gh_issue_list, gh_run_list 等）输出中都混入 `[DIAG-GIT] ExecuteAsync start: ...` 和 `[DIAG-GIT] ExecuteAsync end: ...` 调试日志
- **根因**: `Console.Error.WriteLine` 硬编码，无条件输出，不受 `JCC_DEBUGLOG` 环境变量控制
- **影响**: 客户看到的输出被调试信息污染，无法区分正常输出和调试信息
- **修复方案**: 改用 `Diag.WriteLine` 或 `ILogger.LogDebug`，受 `JCC_DEBUGLOG` 环境变量控制
- **ADR 0080 情况**: 2 (输入输出格式错误)
- **修复提交**: `26dbbf298` fix: GitCommandRunner/GitHubCommandRunner诊断输出改用ILogger替代Console.Error.WriteLine
- **验证**: 重新编译后 `gh_pr_list` 输出干净，无 [DIAG-GIT] ✅

### 问题2：gh_repo_list / gh_run_list 输出原始 API JSON（中严重度）

- **位置**: gh_repo_list, gh_run_list 工具
- **现象**: 直接输出 GitHub REST API 原始 JSON 响应，没有结构化展示（如表格、简要列表）
- **影响**: 工具名是"列出仓库"/"列出运行"，但输出是原始 API 响应，词不达意
- **修复方案**: 添加人类可读的格式化输出（如 `gh_pr_list` 的表格格式），原始 JSON 仅在 `--json` 模式下输出
- **ADR 0080 情况**: 5 (词不达意)

### 问题3：mcp_schema 调用示例未按具体 schema 生成（中严重度）

- **位置**: mcp_schema 命令
- **现象**: 所有工具都显示相同的通用示例 `{"key":"value"}`，未根据实际参数 schema 生成具体示例
- **影响**: AI 和用户无法从 schema 直接知道如何调用，需要猜测参数名（实测中我猜错了 `directory_path` 和 `setting`）
- **修复方案**: 根据工具的 properties 和 required 字段生成具体示例，如 `{"directory_path":"<path>","recursive":false}`
- **ADR 0080 情况**: 2 (格式错误)

### 问题4：参数格式提示不统一（中严重度）

- **位置**: mcp_schema 示例 + 错误提示
- **现象**: jcc 支持两种参数格式（JSON 和 key=value），但 schema 示例只显示 JSON 格式，错误提示只显示 key=value 格式
- **影响**: 用户和 AI 不知道两种格式都支持，容易混淆
- **修复方案**: schema 示例同时显示两种格式；错误提示也同时提两种格式
- **ADR 0080 情况**: 2 (格式错误)

### 问题5：powershell 工具 Windows 上默认禁用（低严重度）

- **位置**: powershell 工具
- **现象**: Windows 上默认禁用，需 `JCC_USE_POWERSHELL_TOOL=1` 环境变量
- **影响**: 错误信息未解释为什么禁用，只说"Set JCC_USE_POWERSHELL_TOOL=1 to enable"
- **修复方案**: 错误信息补充禁用原因（如安全考虑、沙箱限制等）
- **ADR 0080 情况**: 6 (跨进程无法使用)

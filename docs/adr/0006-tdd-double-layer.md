# 0006. 双层 TDD

- 状态：accepted
- 日期：2026-08-29
- 决策者：项目架构组

## 背景

项目既有对外 CLI 接口（进程级交互），又有内部组件单元。单层 TDD 无法覆盖跨进程协议契约，纯单元测试又无法验证端到端链路。Bug 修复时若直接改代码，缺乏复现和定位证据。

## 决策

**双层测试驱动开发，强制循环**：

### 功能开发循环
```
🔴 E2E 红 → 🔴 单元红 → 🟢 单元绿 → 🔵 重构 → 🟢 E2E 绿
```
- E2E 层（仅对外接口变更时）：先写会失败的 E2E 测试定义契约，独立 exe 进程级交互模拟
- 单元层：E2E 红灯下开始红绿循环，先写行为测试后写输入测试
- 铁律：先 E2E 红灯 → 才允许单元测试 → 才允许生产代码

### Bug 修复循环
```
bug → 🔴 E2E 红(复现) → 🔴 单元红(定位根因) → 🟢 单元绿(修复) → 🟢 E2E 绿(验证集成)
```
- 铁律：禁止直接改代码修 bug → 先写 E2E 复现 → 确认失败 → 写单元定位根因 → 确认失败 → 才允许修复

### 例外
- 纯 DTO/枚举无需 TDD
- 纯内部重构可仅走 🔴 单元红 → 🟢 单元绿 → 🔵 重构
- 纯内部 bug 可仅走单元测试复现 → 修复循环

## 替代方案

1. **只单元测试**：放弃。无法验证跨进程协议、MockServer 联合、真实文件系统等集成行为。
2. **只 E2E 测试**：放弃。E2E 启动慢、定位难，不适合快速红绿循环。
3. **先写代码再补测试**：禁止。违反 TDD 铁律，发现无测试的生产代码要先移到 `.xxx/` 再从 E2E 失败测试开始。

## 后果

- 正面：契约先定义、bug 可复现、回归有保护
- 负面：E2E 测试启动慢（启动 jcc.exe + MockServer），需 `--await` 超时兜底；双层维护成本高
- 中性：E2E 用真实 MockServer exe + 端口配置，不模拟对话

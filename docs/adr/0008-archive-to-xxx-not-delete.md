# 0008. .xxx 归档而非删除

- 状态：accepted
- 日期：2026-08-29
- 决策者：项目架构组

## 背景

重构、迁移、清理时经常需要移除文件。直接删除 = 无法回滚 = 灾难性后果：丢失审计追踪、无法追溯历史、违反渐进式安全原则。

## 决策

**禁止删除文件，统一移动到项目根目录 `.xxx/` 目录归档。**

规范：
- **目标位置**：`{RepoRoot}\.xxx\`（如 `D:\project\w3\.xxx\`），禁止移到子目录下的 `.xxx/`
- **命令**：用 `Move-Item`，禁止用 `git mv`（git mv 会 staged 移动记录，且子目录 .xxx 不在 gitignore 中会污染编译）
- **格式**：`.xxx/{原文件名}.{原后缀}.{时间戳}.del`（如 `ICommandRewriter.cs.20260824.del`）
- **.xxx 在 .gitignore 中**：归档文件不被 git 跟踪，原文件显示为 `D`(deleted)，commit 记录删除

移走后必须修复引用（否则编译失败 CS1574/CS0246）：
1. XML 注释中 `<see cref="旧类名"/>` → 改为文字描述
2. `GlobalUsings.cs` 中旧命名空间 → 删除该 `global using` 行
3. 旧测试文件也一并移走（引用旧类的测试同样归档）

## 替代方案

1. **直接 `Remove-Item` / `del` / `rm`**：禁止。不可回滚，灾难性后果。
2. **`git mv` 到归档目录**：放弃。会 staged 移动记录，且子目录 .xxx 不在 gitignore 中会污染编译。
3. **git 归档分支**：放弃。切换分支才能查看历史文件，日常导航不便。

## 后果

- 正面：文件可回滚；审计追踪完整；commit 记录显示删除（原文件 `D` 状态）
- 负面：`.xxx/` 目录会积累文件，需定期清理（但 git 不跟踪，不污染仓库）
- 中性：归档文件命名带时间戳，避免重名

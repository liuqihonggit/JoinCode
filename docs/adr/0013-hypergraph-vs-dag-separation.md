# 0013. 超图与 DAG 分工

- 状态：accepted
- 日期：2026-08-29
- 决策者：项目架构组

## 背景

项目工具调度需要表达"执行顺序+硬依赖"和"评分共享+链路推荐"两种关系。曾考虑用统一的数据结构（超图或 DAG）同时表达两者。

## 决策

**超图与 DAG 不统一，各管各的**：

- **DAG 管"执行顺序 + 硬依赖"**：拓扑排序、环检测、增量重算
- **超图管"评分共享 + 链路推荐"**：语义关联、权重传播

当前 `ToolHyperedge.ChainOrder` 是 `string[]?`（简单线性链），是 DAG 的特例。

**升级条件**：当 ChainOrder 需要支持分支/汇合（如"分析后可走代码生成或测试生成两条路"）时，改用 `Dag<string>` 替代 `string[]`。

## 替代方案

1. **统一用超图**：放弃。超图不擅长表达严格拓扑顺序和环检测。
2. **统一用 DAG**：放弃。DAG 不擅长表达多对多的评分共享和权重传播。
3. **强行统一为一种结构**：禁止。在无实际需求时过度抽象，增加复杂度。

## 后果

- 正面：各结构职责清晰，按需使用
- 负面：两套结构需分别维护
- 中性：ChainOrder 当前是线性链，未来可升级到 `Dag<string>`

# 0016. 参数传接口不传属性

- 状态：accepted
- 日期：2026-08-29
- 决策者：项目架构组

## 背景

代码中存在把对象属性拆开作为函数参数传递的反模式，如 `bool isBash = shell.Type == ShellType.Bash` 然后传 `isBash` 给下游。这导致：调用方需提前知道下游需要什么；新增属性需改所有调用点；丢失上下文。

## 决策

**函数参数尽可能传父类/接口/完整对象，到了末尾才拆开使用。**

适用范围：
1. 构造函数参数：传接口/完整对象
2. 方法参数：传接口/完整对象，除非方法只需要一个原始值（如 `int timeoutMs`）
3. 中间件管道：传 `TContext` 上下文对象，不传上下文的某个属性

**例外**：当拆开的属性是原始类型且语义独立（如 `string filePath`），不需要传整个 `IFileSystem`。

**重构策略**：渐进式，每次发现一个就修一个，禁止一次性大规模重构。

## 替代方案

1. **全部传完整对象**：放弃。原始类型参数（如 `int timeoutMs`）无需包装，过度封装。
2. **全部拆开传属性**：放弃。丢失上下文，调用方需知道下游需求，新增属性需改调用点。
3. **一次性大规模重构**：禁止。违反渐进式开发（见 ADR 0007），风险高。

## 后果

- 正面：调用方简单；新增属性无需改调用点；上下文完整
- 负面：部分方法签名变长（传完整对象）
- 中性：例外情况（原始类型语义独立）保留拆开传参

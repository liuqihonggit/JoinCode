# 0019. 枚举 + EnumValue + 源码生成器

- 状态：accepted
- 日期：2026-08-29
- 决策者：项目架构组

## 背景

项目中大量有限集合的字符串常量（模型名、角色名、状态名等），早期手动维护 KV 映射字典，重复且易错。新增值需改多处代码。

## 决策

1. **有限集合的字符串常量必须枚举化**：凡有限个可选值的字符串标识，必须定义枚举 + `[EnumValue]`，利用源码生成器自动生成 `XxxConstants` + `XxxExtensions`
2. **禁止手动维护 KV 完全相同的映射字典**：当 Key == Value 时（如 `"gpt-4o" → "gpt-4o"`），直接用 `EnumType[]` + `ToValue()` 遍历匹配
3. **枚举是唯一数据源**：字符串值由 `[EnumValue]` 定义一次，所有消费方通过 `ToValue()`/`FromValue()`/`XxxConstants` 获取，禁止在消费方重复硬编码
4. **Contains 匹配场景**：对需模糊匹配（如 `modelId.Contains("gpt-4o")`）的场景，用 `EnumType[]` 按优先级排列，遍历时 `model.ToValue()` 获取匹配串
5. **一个枚举可以多个特性注释**

## 替代方案

1. **手动维护映射字典**：放弃。重复、易错、新增值需改多处。
2. **用常量类（public const string）**：放弃。无类型安全，无法遍历所有值。
3. **运行时反射读取特性**：放弃。反射不兼容 NativeAOT（见 ADR 0002），源码生成器在编译期生成代码。

## 后果

- 正面：唯一数据源，新增值只改枚举一处；编译期生成，AOT 友好；类型安全
- 负面：新增/修改 `[EnumValue]` 后必须 `--no-incremental` 全量重建（源码生成器增量缓存）
- 中性：源码生成器位于 `generators/` 目录（见 ADR 0001 第一层）

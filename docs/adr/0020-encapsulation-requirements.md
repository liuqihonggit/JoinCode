# 0020. 封装要求

- 状态：accepted
- 日期：2026-08-29
- 决策者：项目架构组

## 背景

项目作为 SDK + CLI 双形态发布，需严格控制公开接口暴露面，同时兼顾性能（AOT + GC）和可维护性。

## 决策

| 规则 | 说明 |
|------|------|
| API 粒度 | 尽可能少暴露公开接口，测试用 `internal` 类 |
| 字符串性能 | 用 `Span` 消除性能差异，用只读类型消除多线程不安全 |
| 类拆分 | 字段太多时拆成多个类，封装层次更清晰 |
| 枚举扩展 | 用 `[EnumValue]` + 源码生成器遍历特性收集函数，实现扩展（见 ADR 0019） |

## 替代方案

1. **大量公开接口方便测试**：放弃。公开面大破坏封装，且 API 变更影响外部消费方。
2. **用 string 而非 Span**：放弃。热路径字符串操作性能差，且 AOT 下 Span 更友好。
3. **大类不拆分**：放弃。字段过多导致类职责不清，难维护。

## 后果

- 正面：公开面小，API 稳定；性能优；类职责清晰
- 负面：测试需访问 internal 成员需 `InternalsVisibleTo` 或测试同程序集
- 中性：Span 在 AOT 下零分配，但需开发者熟悉 Span API

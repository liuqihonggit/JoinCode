# 0027. TreatWarningsAsErrors 零警告容忍

- 状态：accepted
- 日期：2026-08-29
- 决策者：项目架构组

## 背景

项目强制 NativeAOT（ADR 0002），AOT 不兼容代码在编译期会产生警告（IL2026、IL3053 等）。若警告被忽略，这些代码会在运行时崩溃。同时项目有自定义分析器（JCC5002、JCC9006），需要强制遵守。

## 决策

**所有源码项目启用 `TreatWarningsAsErrors=true`，零警告容忍。**

效果：
- 任何警告（包括 AOT 兼容性警告、自定义分析器警告）都视为编译错误
- 迫使开发者在编译期解决所有问题，而非忽略
- 配合 AOT 分析器形成编译期安全网

## 替代方案

1. **允许警告**：放弃。AOT 不兼容警告被忽略后，运行时 trim 失败崩溃，难以调试。
2. **仅 AOT 警告视为错误**：放弃。自定义分析器（JCC5002/JCC9006）同样需要强制遵守。
3. **逐项目启用**：放弃。容易遗漏新项目，全局启用更安全。

## 后果

- 正面：编译期捕获所有问题；代码质量高；AOT 运行时安全
- 负面：编译严格，开发者需处理所有警告，初期成本高
- 中性：新增项目自动继承（通过 Directory.Build.props）

# 0030. E2E 真实服务策略

- 状态：accepted
- 日期：2026-08-29
- 决策者：项目架构组

## 背景

E2E 测试需要验证 CLI 与 MCP 服务端的跨进程交互。早期可能倾向用 Mock 模拟对话，但 Mock 无法验证真实进程启动、端口绑定、JSON-RPC 协议序列、文件系统等集成行为。

## 决策

**E2E 测试用真实服务，不模拟对话。**

具体策略：
1. **MockServer 是真实的服务 exe**：每个用配置文件绑定不同端口，预设对话返回（包括调用 read 工具）
2. **jcc.exe 真实启动**：通过 `-p` 发送对话到本机服务，加端口参数
3. **遇到直接模拟对话的测试 → 删除**：不模拟对话，遇到直接删除
4. **`--await <seconds>` 超时参数**：非交互模式超时自动关闭（超时返回 1234），用于测试兜底
5. **诊断靠加日志点位**：遇到 bug/卡死，加日志点位观察，不自己猜测

## 替代方案

1. **用 Mock 模拟对话**：放弃。Mock 无法验证跨进程协议、真实文件系统、端口绑定等集成行为。
2. **仅单元测试不 E2E**：放弃。违反双层 TDD（ADR 0006），无法验证端到端链路。
3. **用 TestServer 内存服务器**：放弃。不验证真实 HttpListener/端口绑定行为。

## 后果

- 正面：验证真实跨进程交互；发现集成问题；协议契约有保障
- 负面：E2E 启动慢（启动 exe + 绑定端口）；需处理端口冲突；卡死需 `--await` 兜底
- 中性：MockServer 预设脚本配置文件控制返回内容，不同测试用不同配置

# 0036. 纵深防御 L1-L10

- 状态：accepted
- 日期：2026-08-29
- 决策者：项目架构组

## 背景

MCP 传输层面临多种故障：网络中断、服务端崩溃、沙箱拦截、OS 限制、DNS 故障等。单层防护不足以覆盖所有故障模式，需纵深防御。

## 决策

**纵深防御 L1-L10 完整 10 层**：

- L1 健康检查：必须检测沙箱/OS 拦截，不能只做 TCP 端口检查
- L2-L10：逐层递进的防护（重试、熔断、降级、备用链等）

**关键约束**：L1 健康检查不能只做 TCP 端口检查，必须检测沙箱/OS 拦截，否则误判服务可用。

定位文件：`docs/design/TransportFallbackChain.md`、`docs/design/UnifiedResilienceArchitecture.md`

## 替代方案

1. **单层重试**：放弃。无法区分网络故障、服务端崩溃、沙箱拦截等不同故障模式。
2. **仅 L1-L3**：放弃。故障模式多样，3 层不足以覆盖。
3. **L1 仅 TCP 端口检查**：放弃。沙箱/OS 拦截时端口可能仍开放，误判服务可用。

## 后果

- 正面：覆盖所有故障模式；逐层递进，故障在最早层捕获
- 负面：10 层实现维护成本高；层间协调复杂
- 中性：与传输层 Fallback 链（ADR 0033）配合使用

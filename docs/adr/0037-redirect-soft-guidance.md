# 0037. Redirect 软引导而非硬转交

- 状态：accepted
- 日期：2026-08-29
- 决策者：项目架构组

## 背景

命令拦截中，某些命令需要重定向到斜杠命令（如用户输入 `/commit` 的变体时，引导 LLM 调用 `/commit`）。可选方案：硬转交（Dispatcher 直接调用斜杠命令执行器）或软引导（返回提示由 LLM 自行调用）。

## 决策

**Redirect 用软引导（返回提示由 LLM 自行调用），非硬转交。**

- 软引导：Guard/Interceptor 返回提示文本，LLM 读到提示后自行决定调用斜杠命令
- LLM 有自主权，可以决定是否执行、何时执行

定位文件：`docs/design/命令拦截架构改造.md:305`

## 替代方案

1. **硬转交**：放弃。Dispatcher 需调用斜杠命令执行器，跨层耦合，破坏 Dispatcher 纯决策职责。
2. **直接执行斜杠命令**：放弃。绕过 LLM 自主权，用户可能不期望立即执行。
3. **拒绝并提示用户手动输入**：放弃。用户体验差，LLM 本可自动处理。

## 后果

- 正面：Dispatcher 保持纯决策，不跨层耦合；LLM 有自主权
- 负面：LLM 可能不遵循引导（不调用斜杠命令），需提示词强化
- 中性：软引导依赖 LLM 理解能力，强模型效果好

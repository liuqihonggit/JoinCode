# 0125. 语义搜索重排序与图谱加权

- 状态：proposed
- 日期：2026-10-01
- 决策者：用户 + AI

## 背景

当前语义搜索流程：查询文本 → ONNX 嵌入 → 暴力余弦相似度 → 降序排序取 topK → 返回。

问题：
1. **无重排序** — 仅凭余弦相似度排序，查询 "cosine similarity calculation SIMD" 返回 GuiPalette.cs（Score=0.3181）而非 VectorMath.cs（未出现在 topK）。原因：maxSeqLen=32 只取前 32 token，代码块前 32 token 多为 `using`/`namespace` 通用词，稀释了核心语义。
2. **图谱未加权** — 知识图谱关联仅作附加显示（调用方/被调用方），不影响搜索分数。结果间有调用关系的块应加分（说明是同一功能链）。

## 决策

### 重排序（Re-ranking）

向量搜索 oversample topK×3 候选 → 多信号重排序 → 取 topK：

| 信号 | 权重 | 来源 | 说明 |
|------|------|------|------|
| 向量余弦相似度 | 0.5 | ANN 搜索 | 基础语义相似度 |
| 关键词重叠分 | 0.3 | SourceText + SymbolFqn | 查询词在代码块中出现频率 |
| 符号名匹配分 | 0.2 | ContainedSymbolFqns | 查询词与块内 AST 符号名匹配 |

关键词提取：PascalCase 拆分（`CosineSimilarity` → `cosine`, `similarity`）+ 小写化 + 去停用词。

### 图谱加权

对重排序后的 topK 结果，检查结果间的图谱关系：

| 关系 | 加分 | 说明 |
|------|------|------|
| 调用关系 | +0.05 | A 的符号调用 B 的符号（CallGraph） |
| 同文件 | +0.03 | 同一文件的不同块（功能内聚） |
| 同命名空间 | +0.02 | 同一命名空间（模块内聚） |

最终分数 = 重排序分数 + 图谱加权。加权后重新排序取 topK。

## 替代方案

### A. 交叉编码器重排序

用 cross-encoder 模型对 (query, chunk) 对打分。精度最高但需要额外模型（~90MB），推理慢（~50ms/对），与 10s 索引目标冲突。**放弃**。

### B. 增大 maxSeqLen

maxSeqLen 32→128/256，让更多 token 参与嵌入。但 ONNX 推理时间线性增长（32→128 约 4x），5975 块嵌入从 15s→60s，不可接受。**放弃**。

### C. 多向量嵌入（DPR 风格）

对查询和块分别用不同模型嵌入。需要两个模型，增加复杂度和存储。**放弃**。

### D. 仅图谱加权不重排序

只加图谱加权不做关键词重排序。但余弦相似度本身精度不够（maxSeqLen=32 限制），不重排序无法解决根本问题。**放弃**。

## 后果

- **正面**：搜索精度显著提升（关键词匹配直接拉高相关块分数）；图谱加权让功能链上的块聚集在结果中
- **负面**：重排序需遍历 oversample 候选的 SourceText，增加 ~1ms（5975 块×3 oversample）；图谱加权需 O(topK²) CallGraph 查询，topK=10 时 100 次查询 ~5ms
- **风险**：关键词权重过高可能偏向精确匹配而忽略语义相似；需调参（初始 0.5/0.3/0.2）

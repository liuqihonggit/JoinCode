# ADR 0127: 跳表索引表用于增量索引

## 状态

proposed

## 背景

当前 VECIDX4 格式一次性写入整个索引文件，增量更新需重写全部数据。为支持增量索引（只更新变化的块），需要：

1. **分页存储** — 数据按页组织，只修改变化的页
2. **索引表** — 维护块 ID → 页位置映射，快速定位
3. **增量更新** — 新块写入新页，索引表更新指向

索引表需支持：O(log n) 查找/插入/删除、有序范围查询（前缀查询文件路径下所有块）、并发无锁读（适配现有 CAS 架构）、持久化到 mmap 文件。

## 决策

选择 **跳表（Skip List）** 作为索引表数据结构。

## 替代方案

### B+树
- 优点：范围查询更优、缓存友好、内存占用低
- 缺点：实现复杂（~800行，节点分裂/合并/旋转）、并发需 latch crabbing、增量更新有写放大（分裂时重写多节点）、持久化需空闲页表
- 不选原因：实现成本高，并发复杂，当前场景不需要大范围扫描

### LSM-Tree
- 优点：写入极快（追加 WAL）
- 缺点：读放大、需后台 compaction 线程、内存占用高
- 不选原因：读性能要求高（搜索时实时查询），compaction 增加复杂度

### SwissTable（项目已有）
- 优点：SIMD 加速、内存紧凑
- 缺点：无序存储，不支持范围查询；增量更新需 rehash
- 不选原因：不支持有序范围查询（前缀查询文件路径下所有块）

## 跳表设计

### 数据结构
- 泛型 `SkipList<TKey, TValue>` where TKey : IComparable<TKey>
- 概率平衡：每层晋升概率 1/2
- 最大层数：32（覆盖 2^32 = 42亿条目）
- 节点：`SkipListNode` 引用类型，`Next[]` 各层指针

### 操作复杂度
| 操作 | 复杂度 |
|------|--------|
| Search | O(log n) |
| Insert | O(log n) |
| Delete | O(log n) |
| Range | O(log n + k) |

### 并发策略
- 读：无锁（volatile 读 Next 指针）
- 写：CAS（Interlocked.CompareExchange 交换 Next 指针）
- 适配 EmbeddingIndex 现有 CAS 架构

### 持久化
- 跳表序列化到索引表区（文件开头）
- 加载时 mmap 映射，重建跳表（内存中），指向 mmap 数据页
- 增量更新：跳表插入/删除 + 追加新页

## 索引表用途

1. **块 ID → 页位置**：搜索时 O(log n) 定位块元数据
2. **文件路径 → 块 ID 集合**：增量索引时快速定位文件的所有块（范围查询）
3. **文件哈希 → 版本信息**：增量索引时对比哈希判断文件是否变化

## 验收标准

- [x] 跳表实现 O(log n) 查找/插入/删除
- [x] 跳表支持范围查询（前缀查询）
- [x] 跳表并发无锁读
- [x] 跳表持久化 + mmap 重建
- [x] 增量索引：只更新变化的页
- [ ] ADR 0080 手动 exe 验收

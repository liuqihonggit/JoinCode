# 任务：模型/供应商对齐（修复切换模型 404 + 区分供应商与模型）

## 背景
用户报告：切换模型后必现 `404 (Not Found)`（"Both streaming and non-streaming fallback failed"）。

**根因**（已定位）：
- 用户配置 `provider=openai` + `endpoint=https://token.sensenova.cn/v1`（商汤 senseNova，OpenAI 兼容）+ `model=sensenova-6.7-flash-lite`
- GUI `JccChatSession.AvailableModels` = `ModelConfigLoader.GetModels("openai")` → 返回内置 models.json 的 openai 组（gpt-* 系列），**当前模型 `sensenova-6.7-flash-lite` 不在列表**
- 下拉列表被 gpt-* 占满，用户切换任意模型 → 请求发往 senseNova endpoint → 404（senseNova 无 gpt-* 模型）

**CLI 已对齐行为**（`ModelCatalog.EnsureCurrentModelInList`）：即使当前模型不在内置列表，也追加进列表保证可见可选。GUI 缺失该逻辑。

## 目标
1. 修复切换模型 404：模型列表必须**确保当前模型在列**（对齐 CLI `EnsureCurrentModelInList`）
2. **区分供应商和模型**：模型下拉项展示供应商显示名 + 模型显示名（如 `OpenAI · GPT-4o`、`OpenAI · sensenova-6.7-flash-lite`），避免把不同供应商模型混为一谈
3. 持续对齐 CLI `/model` 功能（`/model` 切换、默认模型、供应商维度）

## 架构约束
- `IJccChatSession` 门面接口不变语义；模型选择数据源仍在 Hosting 层组装
- 枚举/供应商名走 `ProviderKind` + `[EnumValue]` + 生成器（ProviderKindConstants/Extensions）
- 模型显示名优先 `ModelEntry.DisplayName`（内置），自定义/当前模型回退为 ID 本身
- GUI csproj 不新增引擎依赖；复用 `ModelConfigLoader`（Abstractions）

## 解决方案
1. **修复 404 根因**：`JccChatSession.AvailableModels` 应用 CLI `ModelCatalog.EnsureCurrentModelInList` 逻辑 —— 当前配置的模型（如 `sensenova-6.7-flash-lite`）即使不在内置 models.json 也追加进列表。下拉框默认选中当前模型，用户不主动切换就不会 404。
2. **区分供应商和模型**：模型下拉项展示 `供应商显示名 · 模型显示名`（如 `OpenAI · GPT-4o`、`OpenAI · sensenova-6.7-flash-lite`）。VM 层构建展示模型（`ModelId + DisplayName + ProviderName`），不破坏 `IJccChatSession` 接口语义。
3. **对齐 CLI `/model` 完整行为**（后续）：切换模型时持久化 `modelId` 到 settings.json（CLI 用 `configService.SetAsync("modelId", ...)`）；`/model default` 恢复默认。

# 任务：终端式消息布局（去气泡 + 思考实时蹦字）

## 背景

用户反馈当前 GUI 是"QQ 式两头像对话"，但看不到 AI 思考过程、diff 修改代码行、打字机效果。
经勘察（2026-08-09），UI 四层链路（引擎适配器 → ChunkProcessor → MainViewModel → XAML 模板）均已支持三类事件，
141 个 GUI 测试全绿。真正原因是：

1. **思考过程看不到**：思考消息默认折叠（`IsThinkingCollapsed`），需点击才展开，且折叠交互在流式期间不可见。
2. **diff 看不到**：仅当模型触发文件编辑类工具且返回 `StructuredPatch` 才渲染 —— 普通聊天不会触发。
3. **打字机**：流式事件逐 chunk 到达，但思考被折叠隐藏，正文逐块刷新感知弱。

## 实施记录

### M1 终端式消息模板（去气泡保留彩色）

- **MainWindow.axaml** DataTemplate：外层 `Border`（气泡圆角/背景/左右对齐）改为 `StackPanel`（日志流）。保留角色文字色（`BoolToRoleBrush`）+ 思考/工具 `KindLabel` 彩色标签 + 时间戳 + 输出中 ●。
- **移除**：`BoolToHorizontalAlignmentConverter`（左右对齐）、`BoolToBubbleBackgroundConverter`、`KindToBubbleBackgroundConverter`（气泡背景）。无生产引用。
- **保留**：气泡配色 token（`BubbleThinking`/`BubbleToolCall` 等）仍被 MarkdownView 引用块与 DiffViewer 背景使用，不删。
- 思考消息移除折叠按钮（▶ 点击展开），默认全展开实时蹦字。
- **用户决策（2026-08-09）**：去气泡保留彩色；思考默认全展开。

### M2 思考消息默认展开

- `ChatUiMessage._isThinkingExpanded` 默认值 `true`（原 `false`）。思考内容流式逐字追加实时可见。
- `ToggleThinkingCommand` 保留（支持手动收起），折叠摘要 UI 移除。
- 测试更新：`ThinkingMessage_DefaultsToCollapsed` → `DefaultsToExpanded`；toggle 测试改为收起→展开；非思考消息 toggle 无效果断言改为 true。

### M3 修复既有 flaky：RemoveSession_DeletesPersistedFile

- 根因：测试同步执行 `SendCommand.Execute(null)`（异步 fire-and-forget）后立即 `RemoveSession`，而 `SendAsync` 的 `finally { SaveActiveSession() }` 异步完成会重新写回文件 → `store.Load` 偶发非 null。
- 修复：改为 `async Task` + `Task.Run(...).WaitAsync(Timeout)` 等待发送完成再删除。
- 该 flaky 与终端式改动无关，是既有竞态，顺手修复。

### 引擎思考链路验证（MockServer）

- 构造含 `thinking_content` 的临时 MockServer 配置，启动 `JoinCode.OpenAI.MockServer.exe --port 19901`。
- jcc CLI（真实引擎，同 ChatService 链路）连 MockServer：正常返回正文，`[READY]/[DONE]/[EXIT]`。
- 引擎层：`OpenAIQueryService` 解析 `reasoning_content` → metadata → `ChatStreamChunkProcessor` 产生 `ChatStreamEvent.Thinking`（已有测试覆盖）。
- **结论**：思考蹦字链路完整（MockServer 流式 → 引擎 → VM → UI）。用户真实模型 sensenova 是否返回 reasoning_content 由模型决定；若模型不支持，思考消息不出现但正文打字机仍逐块刷新。

# Avalonia 图形界面宿主设计文档

> 版本: v0.1（骨架阶段）
> 日期: 2026-08-06
> 目标: 进程内承载 JoinCode 智能体引擎，提供聊天式守卫的图形界面，UI 与引擎解耦。

## 1. 背景与目标

当前工程是纯 CLI（TUI 已在前代移除）。用户希望有一个 Avalonia (WPF 类跨平台) 图形界面来承载智能引擎。本次交付为**设计文档 + 项目骨架**，核心诉求是**不耦合**：UI 层不得依赖引擎内部组件实现。

### 关键决策

| 项 | 决策 | 理由 |
|----|------|------|
| 托管方式 | **方案B（进程内）** | 复用 `AddAiWorkflowServices` 组合根，UI 调用 `IChatService`，无 IPC 开销 |
| UI 框架 | Avalonia 11.3.x | 支持 .NET 10（11.12 起），跨平台，AOT 兼容 |
| MVVM | CommunityToolkit.Mvvm | 轻量、AOT 友好、成熟 |
| 解耦边界 | **Abstractions 门面接口** | UI 只依赖 `IChatService`/`IQueryEngine` 等接口，不引内部实现 |
| 工程位置 | `app/JoinCodeGui/` | 隶属 App 层第七层，新增独立 csproj + slnx |

## 2. 解耦架构（进程内）

```
JoinCodeGui (Avalonia App)
  ├── Views/            (.axaml 视图 + code-behind)
  ├── ViewModels/       (CommunityToolkit.Mvvm)
  │     └── 仅依赖 Abstractions 门面接口
  └── Hosting/          (宿主适配器，唯一允许触碰 Composition 的地方)
        └── JccHostAdapter  (inner, 只在骨架阶段内聚)
           └── AddAiWorkflowServices(config) → IServiceProvider → 解析 IChatService
```

**解耦铁律**: UI 层（Views/ViewModels）**禁止**引用 `Core.Brain` / `Core.Hands` / `Composition` 等具体程序集命名空间，只允许引用
- `JoinCode.Abstractions.*`（门面接口与 DTO）
- `JoinCode.Gui.*`（自有的 ViewModel / Hosting 门面）

引擎的具体组装全部收敛在 `Hosting/JccHostAdapter` 这一个文件内。

## 6. 编译配置注意点

| 全局项 | Avalonia 需要的覆盖 |

| `TreatWarningsAsErrors=true` | 保持，但本项目统一在 csproj 处理 |
| `RepoRoot` / `OutputPath` | 全局已指向 `artifacts/`，正常继承 |
| AOT 分析器 | Avalonia 本身兼容，暂不排除 |

（骨架阶段无需额外覆盖，后述实现时若 AOT 分析器误报再局部处理）

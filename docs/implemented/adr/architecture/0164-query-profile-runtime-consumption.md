# ADR 0164：查询中间件由 profile 装配，查询引擎持有固定终点

状态：accepted（2026-11-23。验收记录见 [TASK128](../../../../proposed/task/TASK128-query管道profile生产接线.md)）

## 背景

`AddDataDrivenPipelines` 已组装 `query-pipeline`，但查询引擎另外枚举 DI 中间件。两套清单不一致：YAML 声明的查询限流无运行期效果，而请求前预算与消息转储只在 DI 链中。

## 决策

有显式查询管道装配的宿主使用该管道，不再合并 DI 中间件集合；无装配的独立引擎保留本地构建。延迟解析管道以避开宿主的引擎依赖环。引擎在每轮上下文绑定核心委托；装配层只追加一个固定终点，不引用引擎实例。初始组装和切换使用同一目标 profile 快照来解析节点及其参数，避免在 `ProfileSwitching` 提交前读取旧 `Current`。

## 考虑过的替代方案

- 保留生产 DI 链、撤掉 `query-pipeline` 声明：改动少，但无法兑现现有配置的节点启停、顺序和限流参数。
- 将查询核心也声明为 profile 节点：配置可以漏掉或排除核心，导致查询没有模型调用或完成事件；核心必须是引擎固定终点。

## 后果

生产查询、含工具/stop hook 的内部迭代，共用一次查询级限流入口；它不等同于逐次模型调用限流。profile 切换会创建新窗口。配置中排除全部可选节点时仍运行核心。独立宿主不承担 profile 的依赖。

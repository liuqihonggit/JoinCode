# 会话隔离多级路由 + Entity一体化缓存 + 单线程空闲扫描改造

> 创建: 2026-08-07
> 状态: 设计待确认
> 决策来源: 用户确认 — ①会话id用ObjectId ②注册名用ObjectType枚举 ③整合为单一ReaperScheduler ④所有Entity不跨会话,跨会话必须拷贝 ⑤缓存+Entity一体化

## 1. 问题诊断

### 1.1 当前架构缺陷

| 缺陷 | 现状 | 风险 |
|------|------|------|
| ObjectId 全局自增无会话维度 | `ObjectIdManager._objects` 是进程级全局 map | 任何拿到 ObjectId 的代码都能跨会话访问 Entity，插件恶意/误用可窃取其他会话数据 |
| 会话隔离靠文件系统 | worktree 物理隔离，内存级无隔离 | 同进程内多会话共享内存，Agent A 能 `ObjectIdManager.Get<Agent>(B的id)` |
| 缓存分散无统一生命周期 | 62 处 ConcurrentDictionary 各自为政 | 缓存项无 ObjectId、无超时、无回收、会话结束不清理 → 内存泄漏 |
| 两个并行扫描器 | EntityReaper(定时) + ShellProcessWatchdog(30s) | 双重扫描浪费、可能竞争、非空闲驱动、不按会话隔离 |
| AgentWorktreeService/Manager Dispose 不清理字典 | `DisposeAsync` 只释放锁 | worktree 泄漏风险 |

### 1.2 用户要求的目标架构

```
每个会话 = 独立世界 (像两个独立系统)
所有 Entity 不跨会话, 跨会话必须拷贝
插件通过跳转 (sessionId, objectId) 获取内部元素 (AOT 友好, 无反射)
全局只有一个后台线程, 空闲事件驱动, 按会话隔离轮流扫描
缓存项本身是 Entity, 纳入回收体系
```

## 2. 架构设计

### 2.1 多级路由表 (核心)

```
SessionRouter (单例, 进程级)
  └─ map<ObjectId sessionId, SessionScope scope>     ← 第一级: 会话隔离
       └─ SessionScope
            ├─ ObjectId SessionId
            ├─ map<ObjectType type, HashSet<ObjectId> ids>  ← 第二级: 类型分桶
            ├─ map<ObjectId, Entity> entities               ← 第三级: 实际存储
            ├─ ISessionCache Cache                          ← 会话级缓存
            └─ void Dispose()  ← 会话结束清理所有 Entity + 缓存
```

**关键API**:
- `SessionRouter.GetOrCreateScope(sessionId)` → SessionScope
- `SessionRouter.Resolve<T>(sessionId, entityId)` → T? (跳转获取,插件用)
- `SessionRouter.CloneTo<T>(entity, targetSessionId)` → T (跨会话拷贝)
- `SessionScope.Register(entity)` / `Unregister(entityId)`
- `SessionScope.GetAll<T>()` → 会话内按类型批量获取

### 2.2 Entity 改造

```csharp
public abstract class Entity : IDisposable
{
    public ObjectId ObjectId { get; }
    public ObjectId SessionId { get; }      // 新增: 所属会话
    // ... 其余不变
    
    protected Entity(ObjectType type, ObjectId sessionId, string? displayName = null)
    {
        SessionId = sessionId;
        ObjectId = new ObjectId(type, displayName);
        // 自动注册到 SessionRouter (不再注册到全局 ObjectIdManager)
        SessionRouter.Register(this);
    }
}
```

**兼容策略**: `ObjectIdManager` 保留作为"全局视图"调试入口,但生产代码改走 SessionRouter。Entity 构造增加 sessionId 参数,旧调用点渐进式迁移。

### 2.3 缓存+Entity一体化

```csharp
public sealed class CacheEntryEntity : Entity
{
    public string CacheKey { get; }
    public object? Value { get; set; }       // AOT: 用 JsonElement 或泛型
    public DateTime? ExpiresAt { get; set; }
    public long HitCount { get; set; }
    public long SizeBytes { get; set; }
    
    // CanReclaim: 过期 或 (会话结束 且 未被引用)
    public override bool CanReclaim() 
        => ExpiresAt.HasValue && DateTime.UtcNow > ExpiresAt.Value
           || LifecycleState == EntityLifecycle.Persisted;
}
```

**会话级缓存**: 每个 SessionScope 持有 `ISessionCache`,内部用 `MapRegistry<string, CacheEntryEntity>`。会话 Dispose 时所有 CacheEntryEntity 一起 Dispose。

**现有62处 ConcurrentDictionary 迁移策略**: 渐进式,先迁移高频读写的(AgentRegistry/PermissionCache/HookCache),低频的后续批次。

### 2.4 ReaperScheduler (单后台线程,空闲驱动)

```csharp
public sealed class ReaperScheduler : IDisposable
{
    private readonly BlockingCollection<ScanTask> _queue;
    private readonly Thread _scanThread;     // 唯一后台线程
    private readonly List<IScanStrategy> _strategies;
    
    // 空闲事件订阅 (Agent 空闲/消息队列空/CLI 等待输入)
    public void SubscribeIdleSource(IObservable<IdleEvent> source);
    
    // 注册扫描策略
    public void AddStrategy(IScanStrategy strategy);  // EntityReaper + ShellWatchdog 成为策略
    
    // 按会话隔离轮流扫描
    private void ScanLoop()
    {
        foreach (var scope in SessionRouter.GetAllScopes())  // 轮询每个会话
            foreach (var strategy in _strategies)
                strategy.Scan(scope);  // 只扫描该会话的 Entity
    }
}
```

**IScanStrategy 接口**:
```csharp
public interface IScanStrategy
{
    void Scan(SessionScope scope);  // 按会话扫描,不再扫全局
}
```

**现有 EntityReaper 改造**: 实现 `IScanStrategy`,从扫 `ObjectIdManager.GetAll()` 改为扫 `scope.GetAll<Entity>()`。
**现有 ShellProcessWatchdog 改造**: 实现 `IScanStrategy`,从扫 `_callbacks` 改为扫 `scope.GetAll<BashProcessEntity>()`。
**现有 BackgroundEntityReaperService 废弃**: 由 ReaperScheduler 替代。

### 2.5 跨会话拷贝机制

```csharp
public interface ICloneable<T> where T : Entity
{
    T Clone(ObjectId targetSessionId);  // 深拷贝到目标会话
}
```

需要跨会话传递的 Entity 实现 `ICloneable<T>`。拷贝时:
1. 新 ObjectId (目标会话)
2. 深拷贝所有字段
3. 注册到目标 SessionScope
4. 原 Entity 不变 (两个独立副本)

## 5. 风险点与对策

| 风险 | 对策 |
|------|------|
| Entity 构造加 sessionId 是破坏性改动,调用点多 | 过渡期保留旧构造(标记obsolete),双注册 ObjectIdManager+SessionRouter,渐进迁移 |
| 62处 ConcurrentDictionary 迁移工作量巨大 | 分批,先迁移高频读写,低频的保留并标记 TODO |
| AOT 下 CacheEntryEntity.Value 用 object? 有 trim 风险 | 用泛型 CacheEntryEntity<T> 或 JsonElement + JsonContext |
| 单后台线程扫描可能成为瓶颈 | 空闲驱动+按会话轮流+每会话有预算(扫N个就yield) |
| 跨会话拷贝深拷贝复杂 | 用 record + with 表达式,或源码生成器生成 Clone 方法 |
| 现有测试依赖 ObjectIdManager 全局视图 | 保留 ObjectIdManager 作为调试视图,测试不改 |

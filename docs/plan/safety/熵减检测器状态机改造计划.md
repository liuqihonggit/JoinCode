# 熵减检测器状态机改造计划

## 1. 目标

将 `ShannonEntropyDetector` 从"连续下降即触发"改为**时间窗口二次确认状态机**，
消除误报。同时统一循环检测+干预的所有配置到 `LoopInterventionOptions`，
检测器构造函数参数**去除默认值**，强制从配置类显式传参。

### 核心行为变更

```
改造前: 连续4轮熵递减 → 立即触发 IsLoopDetected=true（易误报）
改造后: 连续4轮熵递减 → 进入 Suspected 状态（不触发）
        5s窗口内再次触发 → Confirmed 状态 → IsLoopDetected=true（确认死循环）
        5s窗口超时 → 复位到 Monitoring（误报消除）
```

确认后由现有 `LoopInterventionMiddleware` 接管分级兜底：
Level1 注入上下文 → Level2 硬截断重连 → Level3 压缩上下文。

## 3. 状态机设计

### 3.1 状态定义

```
┌─────────────┐     decline>=threshold     ┌─────────────┐
│  Monitoring  │ ─────────────────────────→ │  Suspected   │
│  (监控中)    │                             │  (疑似,待确认) │
└─────────────┘                             └─────────────┘
      ↑                                           │
      │ timeout(>5s)                    decline>=threshold
      │ && within window(<=5s)                     │
      └────────────────────────────────────────   ↓
                           ┌─────────────┐
                           │  Confirmed   │
                           │  (确认死循环) │
                           └─────────────┘
                                  │
                        entropy recovered (decline<threshold)
                                  │
                                  ↓
                           回到 Monitoring
```

### 3.2 状态转换规则（链式）

| 当前状态 | 事件 | 下一状态 | IsLoopDetected | 说明 |
|----------|------|----------|----------------|------|
| Monitoring | decline >= threshold | **Suspected** | false | 第一次疑似，记录时间戳 |
| Monitoring | decline < threshold | Monitoring | false | 正常监控 |
| Suspected | decline >= threshold && elapsed <= 5s | **Confirmed** | **true** | 5s内二次触发，确认 |
| Suspected | elapsed > 5s && decline >= threshold | **Suspected** | false | 超时复位后重新疑似 |
| Suspected | elapsed > 5s && decline < threshold | **Monitoring** | false | 超时复位，误报消除 |
| Suspected | decline < threshold && elapsed <= 5s | Suspected | false | 窗口内等待确认 |
| Confirmed | decline >= threshold | Confirmed | **true** | 持续确认，triggerCount++ |
| Confirmed | decline < threshold | **Monitoring** | false | 熵恢复，复位 |

### 3.3 链式调用表达

状态机通过 `Record(text)` 方法驱动，每次调用返回带 `State` 的 `ShannonEntropyResult`，
状态转换由内部 switch 表达式实现，形成链式流转：

```
Monitoring ──Record──→ Suspected ──Record──→ Confirmed ──Record──→ Monitoring(恢复)
```

## 4. 配置统一方案

### 4.1 设计原则

1. **配置类属性可有默认值** — `LoopInterventionOptions` 及子配置类的属性提供默认值，作为系统默认配置
2. **检测器构造函数参数无默认值** — 强制调用方从配置类显式传参，参数传递统一
3. **测试注入点除外** — 如 `clock: Func<DateTimeOffset>` 仅供测试控制时间，可有默认值

### 4.2 配置结构

```csharp
// LoopInterventionOptions 新增子配置（属性有默认值 = 系统默认配置）
public ShannonEntropyConfig ShannonEntropy { get; set; } = new();

// 子配置类
public sealed class ShannonEntropyConfig
{
    public int WindowSize { get; set; } = 10;
    public int DeclineThreshold { get; set; } = 4;
    public double MinEntropyDelta { get; set; } = 0.05;
    public TimeSpan ConfirmationWindow { get; set; } = TimeSpan.FromSeconds(5);  // 新增
}

// 检测器构造函数（参数无默认值，强制显式传参）
public ShannonEntropyDetector(
    int windowSize,
    int declineThreshold,
    double minEntropyDelta,
    TimeSpan confirmationWindow,
    Func<DateTimeOffset>? clock = null)  // clock 除外，仅测试注入
```

### 4.3 InformationEntropyGuardian 从配置创建检测器

```csharp
// 之前：new ShannonEntropyDetector()  ← 用默认值
// 之后：从 LoopInterventionOptions.ShannonEntropy 显式传参
new ShannonEntropyDetector(
    options.ShannonEntropy.WindowSize,
    options.ShannonEntropy.DeclineThreshold,
    options.ShannonEntropy.MinEntropyDelta,
    options.ShannonEntropy.ConfirmationWindow)
```

## 8. 决策记录

<!-- 决策: 5s内再次触发=死循环（去抖逻辑） -->
<!-- 原因: 死循环频率高，5s内必复现；偶发误报5s后自愈复位 -->
<!-- 替代方案: 5s后仍在触发=死循环（持续逻辑），但去抖逻辑更符合信号处理最佳实践 -->

<!-- 决策: 复用现有 LoopInterventionMiddleware 分级干预 -->
<!-- 原因: 已有 Level1 注入/Level2 重连/Level3 压缩的完整实现，只改检测层即可 -->
<!-- 替代方案: 新写独立兜底策略，但会重复造轮子 -->

<!-- 决策: 配置类属性有默认值，检测器构造函数参数无默认值 -->
<!-- 原因: 配置集中在 config 类，调用方强制显式传参，参数传递统一 -->
<!-- 替代方案: 全部无默认值（配置类也无默认值），但配置类需要启动时强制填充，增加复杂度 -->

<!-- 决策: clock 作为测试注入点保留默认值 null -->
<!-- 原因: clock 不是配置参数，是可测试性注入点，生产环境用 DateTimeOffset.UtcNow -->

## 任务目标

逐个验证 123 个 MCP 工具，确保 `jcc mcp call` 能正常调用。遇到 bug 深入代码理解、复现、修复。

## 验证方法

### 基本命令

```powershell
# 1. 空参数测试（不需要参数的工具）
& "D:\project\w1\artifacts\bin\JoinCode\Debug\net10.0\jcc.exe" mcp call <tool_name> --args '{}' --json 2>&1

# 2. 查看 schema（需要参数时先看 schema）
& "D:\project\w1\artifacts\bin\JoinCode\Debug\net10.0\jcc.exe" mcp schema <tool_name> --json 2>&1

# 3. 带参数调用
echo '{"key":"value"}' > D:\project\w1\.xxx\args.json
& "D:\project\w1\artifacts\bin\JoinCode\Debug\net10.0\jcc.exe" mcp call <tool_name> --args-file "D:\project\w1\.xxx\args.json" --json 2>&1
```

### 结果判定

| 输出 | 含义 | 动作 |
|------|------|------|
| `"isError":false` | ✅ OK | 标记通过 |
| `"isError":true,"text":"Missing required parameter"` | ⚠️ PARAM | 查看 schema，提供最小参数集重试 |
| `"isError":true,"text":"其他错误"` | ❌ BUG | 深入代码定位根因，复现，修复 |
| 无 JSON 输出 / 进程崩溃 | 💀 CRASH | 深入代码定位死锁/崩溃，修复 |

### 修复流程

1. **复现**：用相同参数再次调用，确认稳定复现
2. **定位**：根据错误信息 grep 搜索工具实现代码
3. **理解**：读取工具 handler 源码，理解执行路径
4. **修复**：修改代码，`dotnet build` 编译通过
5. **验证**：重新调用确认修复
6. **记录**：在本文档该工具行标注修复内容

## 注意事项

1. **每次修复后 git commit** — `git add <文件>; git commit -m "fix: <工具名> <修复内容>"`（不 push）
2. **逐个测试** — 不要批量调用，逐个工具验证
3. **desktop 工具** — 部分工具涉及鼠标/键盘操作，用空参数测试不触发副作用即可
4. **code_index 工具** — 需要先 `code_index_rebuild` 建索引才能测试查询类工具
5. **遇到死锁** — 如果 jcc.exe 卡住超过 30 秒，用 Ctrl+C 终止，记录为 CRASH
6. **修复后编译** — `dotnet build <csproj> -c Debug` 确认编译通过
7. **工具实现位置** — grep 搜索 `[McpTool("工具名"` 或 `nameof(工具名)` 定位 handler 代码

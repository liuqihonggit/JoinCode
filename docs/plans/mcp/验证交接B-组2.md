## 修复记录

### 修复1：review 工具空参数卡死（commit: 63c23881d）
- **工具**: `review`（skill 分类）
- **症状**: 空参数调用超时（>30s），进程卡死
- **根因**: `McpCommand.BuildHostAsync` 设置了 `options.NonInteractive = true` 但未设置 `TestEnvironmentDetector.ForceNonInteractive`。`ReviewCommand` 空参数时检测 `IsNonInteractive` 为 false，弹出交互式 Dialog 等待 stdin 输入，MCP 调用无 stdin 导致死锁
- **修复**: `app/JoinCode/Cli/Commands/McpCommand.cs` 的 `BuildHostAsync` 方法中添加 `Core.Utils.TestEnvironmentDetector.ForceNonInteractive = true`
- **影响**: 所有 MCP 调用下的交互式命令（Dialog 等待输入）均修复

### 修复2：McpToolDispatch 生成器未应用方法签名默认值（commit: 2a3a8b3e9）
- **工具**: `REPL`（execution 分类）及所有带默认值参数的工具
- **症状**: 空参数调用时 `action` 参数收到空字符串而非签名默认值 `"execute"`，报 "Unknown REPL action:"
- **根因**: `McpToolDispatchGenerator.cs` 对有 `HasExplicitDefaultValue` 的参数生成 `default(T)` 代码，对 `string` 类型是 `null` 而非签名默认值。且第 203 行未从 `param.ExplicitDefaultValue` 提取实际默认值到 `paramDefault`
- **修复**: 
  1. 第 203 行：从 `param.ExplicitDefaultValue` 提取默认值到 `paramDefault`
  2. `BuildArgumentExpression` 方法：对 string/int/long/double/float/bool 类型，当 `param.HasDefaultValue && param.DefaultValue is not null` 时生成使用实际默认值的绑定代码
- **影响**: 所有带默认值参数的 MCP 工具均正确应用签名默认值

## 注意事项

2. **逐个测试** — 不要批量调用，逐个工具验证

5. **skill 工具** — 大部分是斜杠命令的 MCP 封装，空参数可能就能返回帮助信息
6. **遇到死锁** — 如果 jcc.exe 卡住超过 30 秒，用 Ctrl+C 终止，记录为 CRASH
7. **修复后编译** — `dotnet build <csproj> -c Debug` 确认编译通过
8. **工具实现位置** — grep 搜索 `[McpTool("工具名"` 或 `nameof(工具名)` 定位 handler 代码

5. **验证**：重新调用确认修复
6. **记录**：在本文档该工具行标注修复内容

## 修复记录

### 修复1：review 工具空参数卡死（commit: 63c23881d）
- **工具**: `review`（skill 分类）
- **症状**: 空参数调用超时（>30s），进程卡死
- **根因**: `McpCommand.BuildHostAsync` 设置了 `options.NonInteractive = true` 但未设置 `TestEnvironmentDetector.ForceNonInteractive`。`ReviewCommand` 空参数时检测 `IsNonInteractive` 为 false，弹出交互式 Dialog 等待 stdin 输入，MCP 调用无 stdin 导致死锁
- **修复**: `app/JoinCode/Cli/Commands/McpCommand.cs` 的 `BuildHostAsync` 方法中添加 `Core.Utils.TestEnvironmentDetector.ForceNonInteractive = true`
- **影响**: 所有 MCP 调用下的交互式命令（Dialog 等待输入）均修复

### 修复2：McpToolDispatch 生成器未应用方法签名默认值（commit: 2a3a8b3e9）
- **工具**: `REPL`（execution 分类）及所有带默认值参数的工具
- **症状**: 空参数调用时 `action` 参数收到空字符串而非签名默认值 `"execute"`，报 "Unknown REPL action:"
- **根因**: `McpToolDispatchGenerator.cs` 对有 `HasExplicitDefaultValue` 的参数生成 `default(T)` 代码，对 `string` 类型是 `null` 而非签名默认值。且第 203 行未从 `param.ExplicitDefaultValue` 提取实际默认值到 `paramDefault`
- **修复**: 
  1. 第 203 行：从 `param.ExplicitDefaultValue` 提取默认值到 `paramDefault`
  2. `BuildArgumentExpression` 方法：对 string/int/long/double/float/bool 类型，当 `param.HasDefaultValue && param.DefaultValue is not null` 时生成使用实际默认值的绑定代码
- **影响**: 所有带默认值参数的 MCP 工具均正确应用签名默认值

### 修复3：状态依赖工具状态不满足时返回 Success（commit: 91588847c）
- **工具**: `execute_plan_steps`、`ExitPlanMode`（plan 分类）、`voice_stop_recording`（voice 分类）
- **症状**: 状态不满足时（不在计划模式/未录制）返回 `isError:true`，误导调用方认为工具出错
- **根因**: `PlanModeToolHandlers` 和 `VoiceToolHandlers` 在状态守卫处使用 `ToolResultBuilder.Error()` 而非 `Success()`
- **修复**: 
  1. `PlanModeToolHandlers.cs`: `ExitPlanModeAsync` 和 `ExecutePlanStepsAsync` 检查 `result.ErrorMessage` 包含"不在计划模式"时返回 `Success()`
  2. `VoiceToolHandlers.cs`: `VoiceStopRecordingAsync` 未录制时返回 `Success()` 而非 `Error()`
- **影响**: MCP 调用方不再将状态不满足误判为工具错误

### 修复4：AskUserQuestion camelCase JSON 解析失败（commit: 37860c492）
- **工具**: `AskUserQuestion`（interaction 分类）
- **症状**: 传入 camelCase JSON（`{"question":"..."}`）报 "At least 1 question required"
- **根因**: `QuestionItemListContext` 缺少 `[JsonSourceGenerationOptions(PropertyNameCaseInsensitive = true)]`，camelCase 属性名无法映射到 PascalCase 的 `QuestionItem.Question`/`Header`/`Options`
- **修复**: `services/Mcp/src/User/Serialization/QuestionItemListContext.cs` 添加 `[JsonSourceGenerationOptions(PropertyNameCaseInsensitive = true)]`

### 修复5：生成器 Dictionary<string,JsonElement> 单参数绑定缺失（commit: d8de35c41）
- **工具**: `skill_execute`（skill 分类）及所有带 `Dictionary<string,JsonElement>` 参数的工具
- **症状**: `parameters` 参数传 JSON 对象 `{"target":"x"}` 被当作字符串处理，技能内部收不到参数
- **根因**: `McpToolDispatchGenerator.GenerateArgExtractor` 没有对 `Dictionary<string,JsonElement>` 单参数类型生成绑定代码，走了 string fallback
- **修复**: 在数组处理之后、string 处理之前，添加 Dictionary 类型分支：`EnumerateObject().ToDictionary(p => p.Name, p => p.Value.Clone())`

## 注意事项

2. **逐个测试** — 不要批量调用，逐个工具验证

5. **skill 工具** — 大部分是斜杠命令的 MCP 封装，空参数可能就能返回帮助信息
6. **遇到死锁** — 如果 jcc.exe 卡住超过 30 秒，用 Ctrl+C 终止，记录为 CRASH
7. **修复后编译** — `dotnet build <csproj> -c Debug` 确认编译通过
8. **工具实现位置** — grep 搜索 `[McpTool("工具名"` 或 `nameof(工具名)` 定位 handler 代码

# MCP 工具全量验证 — 工作交接文档 C（组3）

> **文档编号**: C
> **工具数**: 100 个（13 个分类）
> **验证状态**: ⏳ 待验证
> **Git 约束**: 每次完成一个工具修复后必须 `git commit`（不 push），commit 消息格式 `fix: <工具名> <修复内容>`

## 任务目标

逐个验证 100 个 MCP 工具，确保 `jcc mcp call` 能正常调用。遇到 bug 深入代码理解、复现、修复。

## 验证方法

### 基本命令

```powershell
# 1. 空参数测试（不需要参数的工具）
& "D:\project\w1\artifacts\bin\JoinCode\Debug\net10.0\jcc.exe" mcp call <tool_name> --args '{}' --json 2>&1

# 2. 查看 schema（需要参数时先看 schema）
& "D:\project\w1\artifacts\bin\JoinCode\Debug\net10.0\jcc.exe" mcp schema <tool_name> --json 2>&1

# 3. 带参数调用（PowerShell 单引号内花括号可能被解析，用文件方式）
Set-Content -Path "D:\project\w1\.xxx\args.json" -Value '{"key":"value"}' -NoNewline
& "D:\project\w1\artifacts\bin\JoinCode\Debug\net10.0\jcc.exe" mcp call <tool_name> --args-file "D:\project\w1\.xxx\args.json" --json 2>&1
```

### 结果判定

| 输出 | 含义 | 动作 |
|------|------|------|
| `"isError":false` | ✅ OK | 标记通过 |
| `"isError":true,"text":"Missing required parameter"` | ⚠️ PARAM | 查看 schema，提供最小参数集重试 |
| `"isError":true,"text":"其他错误"` | ❌ BUG | �2 深入代码定位根因，复现，修复 |
| 无 JSON 输出 / 进程崩溃 | 💀 CRASH | 深入代码定位死锁/崩溃，修复 |

### 修复流程

1. **复现**：用相同参数再次调用，确认稳定复现
2. **定位**：根据错误信息 grep 搜索工具实现代码
3. **理解**：读取工具 handler 源码，理解执行路径
4. **修复**：修改代码，`dotnet build` 编译通过
5. **验证**：重新调用确认修复
6. **记录**：在本文档该工具行标注修复内容

## 注意事项

1. **每次修复后 git commit** — `git add <文件>; git commit -m "fix: <工具名> <修复内容>"`（不 push）
2. **逐个测试** — 不要批量调用，逐个工具验证
3. **file 工具** — `Read`/`Write`/`Edit` 会真实读写文件，用 `.xxx/` 目录下的临时文件测试
4. **mcp 工具** — `mcp_connect` 等会尝试连接远程服务器，空参数测试即可
5. **sandbox 工具** — `sandbox_enter` 会改变执行环境，测试后记得 `sandbox_exit`
6. **graph 工具** — 需要先 `graph_load` 或构建索引才能查询
7. **遇到死锁** — 如果 jcc.exe 卡住超过 30 秒，用 Ctrl+C 终止，记录为 CRASH
8. **修复后编译** — `dotnet build <csproj> -c Debug` 确认编译通过
9. **工具实现位置** — grep 搜索 `[McpTool("工具名"` 或 `nameof(工具名)` 定位 handler 代码

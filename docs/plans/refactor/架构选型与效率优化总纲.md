## 2. P0 — 资源类树状生长(选型5, 40%→85%)

### 2.1 目标

将 12+ 个后台可卸载资源类继承 `Entity`/`ServiceEntity`/`PluginResourceBase`,使其:
- 可收集到 `ContainerMap[typeName, object]` 容器(选型5核心)
- 具备统一生命周期: 引用计数 + 心跳 + 死亡事件(`PluginResourceBase`)
- 可被后台健康扫描 + 自动卸载/破坏(用户要求:"后台会不断扫描这些资源健康,如果被卸载或者宿主死亡了会自动破坏")

### 2.2 涉及文件树

```

  Infrastructure/Plugins/Plugins/WorkflowPluginHost.cs                   # → PluginResourceBase
  Infrastructure/Plugins/Plugins/ExternalPluginHost.cs                   # → PluginResourceBase
services/
  Eyes/src/Lsp/Internal/Service/LspService.cs                            # → ServiceEntity
  Eyes/src/Lsp/Internal/Service/LspManager.cs                            # → ServiceEntity

  Abstractions/03-hands/Skill/PluginResourceBase.cs                      # 可能需增强
```

### 2.3 设计方案

**关键问题**: `ServiceEntity`/`PluginResourceBase` 是否已实现 `IAsyncDisposable`? 若未实现,需先增强基类(加 `IAsyncDisposable` 接口),否则现有 `DisposeAsync` 调用方断裂。

**步骤0(前置)**: 审计 `ServiceEntity`/`PluginResourceBase`/`Entity` 的接口契约,确认:
- 是否已有 `IAsyncDisposable`/`IDisposable`
- 是否有 `Id`/`TypeName` 属性供 `ContainerMap[typeName, object]` 收集
- 是否有心跳/死亡事件钩子

**继承策略**:

| 资源类型 | 基类选择 | 理由 |
|---------|---------|------|
| 管理器/服务(ConnectionManager/LspManager/BridgeMain/McpHttpServer) | `ServiceEntity` | 长生命周期,无引用计数需求 |
| 会话/轮询(SessionRunner/PeerSessionManager/BridgeWorkPollLoop) | `ServiceEntity` | 长生命周期 |
| 子进程/插件宿主(BridgeSubprocessHandle/WorkflowPluginHost/ExternalPluginHost) | `PluginResourceBase` | 需引用计数+心跳+可卸载 |

**⚠️ 架构决策点(需用户确认)**:
1. `ServiceEntity` 是否要加 `IAsyncDisposable`? 这会影响所有 ServiceEntity 子类
2. 现有 `IConnectionManager`/`ILspService` 等接口是否保留? (保留=接口+基类双继承,删除=仅基类)
3. `ContainerMap[typeName, object]` 容器由谁维护? (新增 `ResourceRegistry` 还是复用现有 DI 容器?)

每个类独立走: 🔴单元红(验证可收集到容器+生命周期) → 🟢单元绿(继承基类) → 🔵重构 → 🟢E2E绿

## 3. P1 — NativeAOT 内联标注(10%→60%)

### 3.1 目标

为热路径方法标注 `[MethodImpl(MethodImplOptions.AggressiveInlining)]`,使 NativeAOT 编译期内联,消除调用开销。

### 3.2 涉及文件

| 文件 | 方法 | 行号 |
|------|------|------|
| `foundation/Abstractions/00-core/Core/Utils/State/StateMachine.cs` | CanTransitionTo/TryTransitionTo/ForceTransitionTo/Reset/GetValidNextStates/IsTerminalState | 53,63,71,90,114,126 |
| `foundation/Abstractions/03-hands/Skill/PluginResourceBase.cs` | EnsureAlive | 71 |
| `core/execution/Brain/src/Context/Services/Loop/ShannonEntropyDetector.cs` | Record | 71 |
| `core/safety/Guard/src/Security/Services/ReadOnlyCommandDetector.cs` | TwoTokenKey/ThreeTokenKey | 485,491 |
| `foundation/Abstractions/00-core/Core/Utils/Text/StringTruncator.cs` | Truncate 重载 | 17,19,33 |

### 3.3 设计方案

**原则**: 仅标注"小方法体 + 热路径"的方法。大方法体标注内联反而增大代码体积,NativeAOT 可能忽略。

**注意**: `StateMachine<TState>` 是泛型类,AOT 下每个实例化独立编译,内联特性对值类型 TState 尤其有效。

### 3.4 TDD 步骤

纯特性标注,无行为变更 → 编译通过 + 现有测试不回归即可提交(无需新增测试)。

### 5.3 设计方案

```csharp
// 改前(三次分配: Select 迭代器 + ToArray 数组 + Join 结果)
string.Join(", ", options.Select(o => $"\"{o}\"").ToArray())

// 改后(.NET 10 Join 直接接 IEnumerable, 一次分配)

```

> 注: 需确认 .NET 10 `string.Join(string, IEnumerable<string>)` 是否已消除中间数组。若是,仅删 `.ToArray()` 即可。

### 5.4 TDD 步骤

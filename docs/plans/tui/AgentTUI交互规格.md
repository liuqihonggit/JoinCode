# Agent TUI 交互规格说明书（补充版）

> 基于多Agent协作的可视化终端界面设计。核心模式：轮询拉取 + 多管道并行 + 队列发送 + 点击穿透 + 分层渲染。

## 一、核心交互模型

### 1.1 多Agent管道模型

```
                         ┌─────────────────────────────────────┐
                         │          输出区（渲染层）           │
                         │  拉取各Agent管道的最新消息          │
                         └─────────────────────────────────────┘
                                      ▲
                                      │ 轮询拉取（每200ms）
                                      │
              ┌───────────────────────┼───────────────────────┐
              │                       │                       │
              ▼                       ▼                       ▼
     ┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐
     │  主Agent管道    │   │ 子Agent001管道  │   │ 子Agent002管道  │
     │  (Agent)        │   │  (SubAgent)     │   │  (SubAgent)     │
     │  ┌───────────┐  │   │  ┌───────────┐  │   │  ┌───────────┐  │
     │  │消息队列   │  │   │  │消息队列   │  │   │  │消息队列   │  │
     │  │Msg1       │  │   │  │Msg1       │  │   │  │Msg1       │  │
     │  │Msg2       │  │   │  │Msg2       │  │   │  │Msg2       │  │
     │  └───────────┘  │   │  └───────────┘  │   │  └───────────┘  │
     └─────────────────┘   └─────────────────┘   └─────────────────┘
              ▲                       ▲                       ▲
              │                       │                       │
              └───────────────────────┼───────────────────────┘
                                      │
                             ┌────────┴────────┐
                             │   消息总线      │
                             │  (MessageBus)   │
                             └─────────────────┘
                                      ▲
                                      │
                             ┌────────┴────────┐
                             │  用户输入队列   │
                             │  [msg1, msg2]   │
                             └─────────────────┘
                                      ▲
                                      │
                             ┌────────┴────────┐
                             │   用户输入栏    │
                             └─────────────────┘
```

### 1.2 关键设计原则

| 原则 | 说明 |
|------|------|
| **拉取模式** | UI不监听推送事件，而是每200ms轮询所有Agent管道，检查是否有新消息 |
| **管道隔离** | 每个Agent拥有独立的消息队列，互不干扰 |
| **统一渲染** | 所有管道的消息按时间戳排序后统一渲染到输出区 |
| **点击展开** | 子Agent在输出区仅显示状态摘要，点击后展开该Agent的完整消息流 |
| **输入队列** | 用户输入不直接发送，先入队列，由调度器按轮次取出发送 |

### 2.2 各区域详细定义

#### 状态栏（第1行）

| 位置 | 内容 | 说明 |
|------|------|------|
| 左 | `⚡ Agent TUI v1.0` | 应用名+版本，绿色高亮 |
| 中 | `Session: #003` | 当前会话ID |
| 中 | `Agents: 4` | 当前活跃Agent总数（主+子） |
| 右 | `⏱ 00:05:23` | 运行时长 |

#### 工具栏（第2行）

| 按钮 | 功能 | 快捷键 |
|------|------|--------|
| `📤 Send Queue: 2` | 显示队列中待发送消息数，点击立即发送全部 | Alt+Q |
| `🔄 Refresh` | 强制刷新所有Agent管道 | F5 |
| `📋 Clear` | 清空输出区（不删除消息，仅视觉） | Ctrl+L |
| `⚙️ Settings` | 打开设置面板 | F10 |

#### 输出区（核心区域）

**类型A：用户消息**
- 右对齐显示
- 颜色：#58a6ff（蓝色）
- 前缀：`👤` 或 `>`

**类型B：主Agent消息**
- 左对齐
- 思考部分：`💭 Thinking: xxx` 灰色（#8b949e），斜体样式
- 正文部分：绿色（#7ee787）
- 代码块：深色背景，保留语法高亮（可选）

**类型C：子Agent卡片（折叠状态）**
- 可点击/可选中
- 状态指示：● 运行中（绿色）/ ● 等待（黄色）/ ● 已完成（蓝色）/ ● 错误（红色）
- 点击后展开为该Agent的完整消息流

**类型D：子Agent消息（展开状态）**
- 边框绘制
- 内部消息流同主Agent格式
- 标题栏显示状态、消息计数

#### 输入区（底部固定）

| 元素 | 规格 |
|------|------|
| 输入框 | 多行，自动扩展高度（1-10行），超过10行滚动 |
| 提示行 | 显示当前队列状态、轮次信息 |
| Send按钮 | 绿色高亮，Enter快捷键 |
| 队列指示 | 实时更新"当前队列: X条待发送" |

## 三、消息生命周期

### 3.1 完整流程

1. **输入验证** - 非空检查、长度检查（最大4000字符）
2. **加入发送队列** - 消息入队，分配队列ID，更新工具栏计数，立即在输出区显示（灰色半透明，标记"待发送"）
3. **轮次调度** - 等待当前轮次完成，轮次到达时取出最早消息，标记"已发送"
4. **分发到Agent管道** - 通过MessageBus分发到主Agent管道，主Agent处理后可能产生子Agent
5. **UI轮询拉取** - 每200ms轮询所有Agent管道，按时间戳排序后渲染
6. **渲染更新** - 增量更新，自动滚动到底部，更新子Agent状态卡片

### 3.2 队列状态机

```
空闲(Idle) → 队列等待(Queued) → 发送中(Sending) → 已发送(Sent) → 下一轮
```

## 四、子代理交互详细规格

### 4.1 状态卡片（折叠状态）

```
格式: 🧩 [SubAgent] {名称} ({状态图标} {状态文字})  [点击{操作}]

状态图标:
  ● 绿色  = 运行中 (Running)
  ● 黄色  = 等待中 (Waiting)
  ● 蓝色  = 已完成 (Completed)
  ● 红色  = 错误 (Error)
  ● 灰色  = 已停止 (Stopped)
```

### 4.2 点击展开行为

1. 卡片原地展开（展开动画 100ms）
2. 显示该Agent的完整消息流
3. 标题栏变为可折叠按钮 `[− 折叠]`
4. 滚动定位到展开区域的顶部

### 4.3 内存管理

- 默认最多同时展开3个子Agent
- 展开第4个时，自动折叠最早展开的那个
- 用户可手动折叠任意Agent

### 4.4 子代理消息流内部格式

```
前缀说明:
  💭 = 思考过程 (灰色)
  🔧 = 工具调用 (橙色)
  📄 = 工具返回 (蓝色)
  💬 = 正文输出 (绿色)
  ⚠️ = 警告 (黄色)
  ❌ = 错误 (红色)
```

## 六、自适应缩放监控

### 6.1 窗口尺寸变化监控

- 钳制尺寸到合理范围 [80x24, 500x200]
- 防抖：200ms内只处理最后一次变化
- 尺寸获取失败时使用默认尺寸 120x40

### 6.2 尺寸变化时的重新布局

1. 获取新尺寸 (width, height)
2. 验证尺寸是否在合理范围
3. 重新计算各区域高度: 输出区 = height - 6行
4. 重新绘制所有组件
5. 恢复滚动位置

### 6.3 监控检查点（每100ms执行）

1. 检查终端尺寸变化
2. 轮询Agent管道
3. 检查输入队列状态
4. 更新运行时长
5. 刷新UI

## 七、开发实现要点

### 技术约束
1. 使用 Terminal.Gui v2.x
2. 目标框架: net10.0
3. 跨平台: Windows/macOS/Linux
4. 不支持鼠标时，所有操作必须键盘可完成
5. NativeAOT 兼容

### 必须实现的接口

```csharp
// 消息管道接口
public interface IMessagePipe
{
    string AgentId { get; }
    string AgentName { get; }
    AgentState State { get; }
    IReadOnlyList<Message> Messages { get; }
    int MessageCount { get; }
    IReadOnlyList<Message> GetNewMessages(DateTime since);
    void AddMessage(Message message);
    void Clear();
}

// 消息结构
public class Message
{
    public string Id { get; set; }
    public string AgentId { get; set; }
    MessageType Type { get; set; }  // User/AgentThinking/AgentContent/ToolCall/ToolResult
    public string Content { get; set; }
    public DateTime Timestamp { get; set; }
    MessageStyle Style { get; set; }  // 颜色、斜体、粗体等
    public Dictionary<string, object> Metadata { get; set; }
}

// 输入队列
public class InputQueue
{
    void Enqueue(UserInput input);  // 加入队列
    UserInput Dequeue();           // 轮次到达时取出
    int Count { get; }
    bool CanSend { get; }          // 是否轮到当前轮次
}
```

### 轮询机制实现

```csharp
public class PollingService
{
    private readonly List<IMessagePipe> _pipes = new();
    private readonly int _pollIntervalMs = 200;
    private DateTime _lastPollTime;
    
    public async Task PollAsync()
    {
        var now = DateTime.UtcNow;
        foreach (var pipe in _pipes)
        {
            var newMessages = pipe.GetNewMessages(_lastPollTime);
            if (newMessages.Any())
            {
                OnMessagesReceived?.Invoke(pipe.AgentId, newMessages);
            }
        }
        _lastPollTime = now;
    }
}
```

### 渲染优先级
1. 高优先级: 用户消息立即渲染（标记"待发送"状态）
2. 中优先级: Agent的思考内容（实时显示）
3. 低优先级: Agent的正文内容（可批量渲染）
4. 最低优先级: 子代理卡片状态更新

### 错误处理要求
1. 任何渲染异常不能导致程序崩溃
2. 管道拉取失败时，显示"⚠️ 拉取失败，重试中..."
3. 队列满时（>100条），阻止新输入并提示
4. 终端尺寸变化异常时，使用安全默认值

### 性能要求
1. 轮询间隔: 200ms，不能低于100ms（避免CPU过载）
2. 渲染帧率: 至少20 FPS
3. 消息量: 支持单Agent管道1000条消息
4. 展开状态: 同时展开不超过3个子Agent
5. 内存: 总消息超过5000条时，自动归档旧消息

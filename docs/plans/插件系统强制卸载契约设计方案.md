## 一、需求来源

用户诉求:**"不写对应的卸载就不允许加载"**。

前两轮设计已实现"卸载时逆序执行撤销链 + 卸载后扫描泄漏",但泄漏只 `LogWarning`,且副作用入口未收敛——插件可在 `Load(IServiceCollection)` 里裸做副作用而不经 `RegisterResource`,框架无法识别,卸载时泄漏。本方案把"事后扫描"升级为"加载时强制契约 + 入口收敛"。

### 1.1 现状缺口(三处)

| # | 缺口 | 位置 | 后果 |
|---|------|------|------|
| 1 | `IWorkflowPlugin.Load(IServiceCollection)` 是抽象方法,子类可裸做副作用 | `IWorkflowPlugin.cs:27` | 副作用绕过 `RegisterResource`,卸载泄漏 |
| 2 | `LoadFromPlugin` 返回 `Action`,作者可返回 `() => { }` 空操作 | `PluginAgentLoader.cs:33-50` | undo 空挂,卸载不清理 |
| 3 | `ScanAfterUnload` 发现泄漏只 `_logger?.LogWarning` | `PluginManager.cs:477-485` | 泄漏不阻断,可重复加载泄漏插件 |

### 1.2 Cordis 的解法(参考)

Cordis 不做编译时强制,而是**架构性收敛**:所有副作用唯一入口是 `ctx`(`ctx.on`/`ctx.tools.register`/`ctx.effect`),`ctx` 内部自动登记撤销。绕过 `ctx` 在 API 层面"不自然"。本方案在此基础上**加一道加载时契约门**,把 Cordis 的"约定"升级为"校验"。

## 二、三方案总览

| 方案 | 强制点 | 时机 | 成本 | breaking |
|------|--------|------|------|----------|
| **B 加载时契约门** | 资源覆盖 + disposer 非空 + 泄漏 throw + 黑名单 | 运行时加载/卸载 | 低 | 否 |
| **C PluginContext 收敛入口** | 副作用唯一入口 `ctx`,签名 `LoadAsync(PluginContext)` | 架构层 | 中 | 是(插件签名) |
| **D Fiber 状态机 + async disposer** | 状态机非法转换 throw + 卸载并发调度 | 运行时/卸载 | 中 | 否(增量) |

**落地顺序**:B(立即满足诉求)→ C(根治入口)→ D(优化卸载并发)。C 的签名变更用 `[Obsolete]` shim 兼容旧插件,过渡期双跑。

## 三、方案 B — 加载时契约门

### 3.1 核心思路

在 `LoadWorkflowPluginAsync` 的 `Load()` + `InitializeAsync()` 之后插入**契约校验门**,校验失败直接 throw,拒绝加载。卸载时 `ScanAfterUnload` 泄漏从 `LogWarning` 升级为 **throw + 黑名单**(拒绝该插件再次加载)。

### 3.2 契约校验内容

| 校验项 | 说明 | 实现 |
|--------|------|------|
| **C1 资源登记覆盖** | 插件声明的每个副作用(命令/钩子/技能/Agent)都在 `Resources` 表里 | 对比 `IPluginAgentProvider.GetAgentDefinitions()` 数量 vs `Resources` 中 `Kind==Agent` 数量;命令/钩子/技能同理 |
| **C2 disposer 非空** | 每个 `PluginResourceBase` 的 `OnResourceDispose` 不是默认空实现 | 用 `IRequireExplicitDispose` 标记接口区分;未实现的资源视为"无清理逻辑",加载时 throw |
| **C3 undo 非空委托** | `LoadFromPlugin` 返回的 `Action` 不能是 null | 包一层 `NonEmptyUndo` 值类型,构造时校验 `Action != null` |
| **C4 卸载后泄漏阻断** | `ScanAfterUnload` 发现泄漏 → throw + 加黑名单 | `_blacklistedPlugins` `FrozenSet<string>`,加载前检查 |

### 3.3 接口定义

```csharp
// foundation/Abstractions/03-hands/Skill/IPluginUnloadContract.cs
namespace JoinCode.Abstractions.Interfaces;

/// <summary>插件卸载契约校验结果</summary>
public sealed record PluginUnloadContract(
    bool IsValid,
    string? Reason,
    IReadOnlyList<string> Violations)
{
    public static readonly PluginUnloadContract Valid = new(true, null, []);
    public static PluginUnloadContract Invalid(params string[] violations) =>
        new(false, string.Join("; ", violations), violations);
}

/// <summary>标记资源需要显式 disposer — 未实现此接口的资源加载时拒绝</summary>
public interface IRequireExplicitDispose
{
    /// <summary>资源特定清理逻辑 — 从 Registry 移除等</summary>
    void OnResourceDispose();
}

/// <summary>非空撤销委托 — 构造时校验非 null,编译期 + 运行期双重保证</summary>
public readonly struct NonEmptyUndo
{
    private readonly Action _undo;
    public NonEmptyUndo(Action undo)
    {
        ArgumentNullException.ThrowIfNull(undo);
        _undo = undo;
    }
    public void Invoke() => _undo();
    public static implicit operator Action(NonEmptyUndo x) => x._undo;
}
```

### 3.4 WorkflowPluginBase 加契约校验方法

```csharp
// foundation/Abstractions/03-hands/Skill/WorkflowPluginBase.cs 新增
public abstract class WorkflowPluginBase : Entity, IWorkflowPlugin, IPluginHeartbeat
{
    // ... 已有成员不变 ...

    /// <summary>
    /// 校验卸载契约 — 加载后由 PluginManager 调用
    /// <para>C1: 资源登记覆盖(子类可覆写做更严校验)</para>
    /// <para>C2: 每个资源实现 IRequireExplicitDispose</para>
    /// </summary>
    public virtual PluginUnloadContract ValidateUnloadContract()
    {
        var violations = new List<string>();
        var snapshot = Resources;
        foreach (var r in snapshot)
        {
            if (r is not IRequireExplicitDispose)
                violations.Add($"资源 '{r.DisplayName}' (Kind={r.Kind}) 未实现 IRequireExplicitDispose,无清理逻辑");
        }
        return violations.Count > 0
            ? PluginUnloadContract.Invalid([.. violations])
            : PluginUnloadContract.Valid;
    }
}
```

```csharp
public async Task<WorkflowPluginHost> LoadWorkflowPluginAsync<TPlugin>(CancellationToken ct = default)
    where TPlugin : class, IWorkflowPlugin, new()

        {
            host.Unload(); host.Dispose();
            RecordPluginMetrics("workflow", "load", false);
            throw new InvalidOperationException(
                $"[INF-PLUGIN-CONTRACT] 插件 '{pluginName}' 拒绝加载: {contract.Reason}");
        }
    }

    // ... 已有后续注册 undo / AddToLoadOrder ...
}

// ScanAfterUnload 升级:泄漏 → throw + 黑名单
private void ScanAfterUnload(string pluginName)
{
    if (!_pluginResourceIds.TryRemove(pluginName, out var resourceIds)) return;
    var report = ResourceScanner.ScanPluginResources(pluginName, resourceIds);
    if (report.HasLeaks)
    {
        // 🆕 加入黑名单,拒绝再次加载
        _blacklistedPlugins = _blacklistedPlugins.Add(pluginName);
        _logger?.LogError("插件 {Plugin} 卸载后有 {Count} 个资源泄漏,已加入黑名单",
            pluginName, report.LeakedResourceIds.Count);
        // 不 throw(卸载已在进行中),但记录并阻断后续加载
    }
}
```

## 四、方案 C — PluginContext 收敛入口

### 4.1 核心思路

新增 `PluginContext`(对齐 Cordis `ctx`),作为插件做副作用的**唯一入口**。每次注册自动返回 undo 并塞进 `_pluginUndoChain`。`IWorkflowPlugin.Load(IServiceCollection)` 改为 `LoadAsync(PluginContext, CancellationToken)`,旧签名标 `[Obsolete]` 做 shim。

### 4.2 PluginContext 接口

```csharp
// foundation/Abstractions/03-hands/Skill/PluginContext.cs
namespace JoinCode.Abstractions.Entity;

/// <summary>
/// 插件副作用唯一入口 — 对齐 Cordis ctx
/// <para>每个注册方法返回 NonEmptyUndo,框架自动登记到撤销链</para>
/// <para>插件无法绕过 ctx 直接访问 IServiceCollection 做副作用</para>
/// </summary>
public sealed class PluginContext
{
    private readonly string _pluginName;
    private readonly IServiceCollection _services;
    private readonly IPluginCommandRegistry _commands;
    private readonly IPluginHookInjector _hooks;
    private readonly IPluginSkillBridge _skills;
    private readonly IPluginAgentLoader _agents;
    private readonly List<NonEmptyUndo> _undoChain = new();
    private readonly List<PluginResourceBase> _resources = new();

    internal PluginContext(
        string pluginName,
        IServiceCollection services,
        IPluginCommandRegistry? commands,
        IPluginHookInjector? hooks,
        IPluginSkillBridge? skills,
        IPluginAgentLoader? agents)
    {
        _pluginName = pluginName;
        _services = services;
        _commands = commands!;
        _hooks = hooks!;
        _skills = skills!;
        _agents = agents!;
    }

    /// <summary>注册 DI 服务 — 粗粒度,撤销 = ServiceProvider.Dispose</summary>
    public void RegisterService<TService, TImpl>(ServiceLifetime lifetime = ServiceLifetime.Singleton)
        where TImpl : class, TService
        where TService : class
    {
        _services.Add(new ServiceDescriptor(typeof(TService), typeof(TImpl), lifetime));
    }

    /// <summary>注册命令 — 返回 undo,自动登记</summary>
    public async Task RegisterCommandAsync(PluginCommandDefinition cmd, CancellationToken ct = default)
    {
        var undo = await _commands.RegisterCommandAsync(cmd, ct).ConfigureAwait(false);
        _undoChain.Add(new NonEmptyUndo(undo));
    }

    /// <summary>注入 Hook — 返回 undo,自动登记</summary>
    public async Task RegisterHookAsync(PluginHookDefinition hook, CancellationToken ct = default)
    {
        var undo = await _hooks.InjectHooksAsync(_pluginName, [hook], ct).ConfigureAwait(false);
        _undoChain.Add(new NonEmptyUndo(undo));
    }

    /// <summary>注册技能 — 返回 undo,自动登记</summary>
    public async Task RegisterSkillAsync(CancellationToken ct = default)
    {
        var undo = await _skills.RegisterPluginSkillsAsync(_pluginName, ct).ConfigureAwait(false);
        _undoChain.Add(new NonEmptyUndo(undo));
    }

    /// <summary>注册 Agent — 返回 undo,自动登记</summary>
    public NonEmptyUndo RegisterAgents(IPluginAgentProvider provider)
    {
        var undo = _agents.LoadFromPlugin(_pluginName, provider);
        var wrapped = new NonEmptyUndo(undo);
        _undoChain.Add(wrapped);
        return wrapped;
    }

    /// <summary>自定义副作用 — 对齐 Cordis ctx.effect(disposer)</summary>
    public void Effect(Func<IDisposable> factory)
    {
        var disposable = factory();
        _undoChain.Add(new NonEmptyUndo(disposable.Dispose));
    }

    /// <summary>登记资源 — 用于契约校验 C1 资源覆盖</summary>
    internal void TrackResource(PluginResourceBase resource) => _resources.Add(resource);

    /// <summary>获取撤销链(逆序) — PluginManager 卸载时调用</summary>
    internal IReadOnlyList<NonEmptyUndo> GetUndoChain() => _undoChain;

    /// <summary>获取登记的资源 — 契约校验用</summary>
    internal IReadOnlyList<PluginResourceBase> GetTrackedResources() => _resources;
}
```

## 五、方案 D — Fiber 状态机 + async disposer

### 5.1 Fiber 状态机显式化

Cordis 有 `PENDING → LOADING → ACTIVE → UNLOADING → DISPOSED`(+ `FAILED`)五态。项目 `Entity` 有生命周期但没显式 Fiber 状态枚举。新增 `PluginFiberState` + 非法转换 throw。

```csharp
// foundation/Abstractions/03-hands/Skill/PluginFiberState.cs
namespace JoinCode.Abstractions.Entity;

public enum PluginFiberState
{
    /// <summary>已声明,依赖未就绪</summary>
    Pending,
    /// <summary>依赖就绪,LoadAsync 运行中</summary>
    Loading,
    /// <summary>运行中</summary>
    Active,
    /// <summary>LoadAsync 抛异常</summary>
    Failed,
    /// <summary>卸载中,disposer 执行中</summary>
    Unloading,
    /// <summary>已卸载,资源全部释放</summary>
    Disposed,
}

/// <summary>Fiber 状态机 — 非法转换抛 InvalidOperationException</summary>
public sealed class PluginFiber
{
    private PluginFiberState _state = PluginFiberState.Pending;
    private readonly object _lock = new();

    public PluginFiberState State => _state;

    public void TransitionTo(PluginFiberState next)
    {
        lock (_lock)
        {
            if (!IsValidTransition(_state, next))
                throw new InvalidOperationException(
                    $"[INF-FIBER-ILLEGAL] 非法状态转换: {_state} → {next}");
            _state = next;
        }
    }

    private static bool IsValidTransition(PluginFiberState from, PluginFiberState to) => (from, to) switch
    {
        (PluginFiberState.Pending, PluginFiberState.Loading) => true,
        (PluginFiberState.Loading, PluginFiberState.Active) => true,
        (PluginFiberState.Loading, PluginFiberState.Failed) => true,
        (PluginFiberState.Active, PluginFiberState.Unloading) => true,
        (PluginFiberState.Unloading, PluginFiberState.Disposed) => true,
        (PluginFiberState.Failed, PluginFiberState.Disposed) => true,
        _ => false,
    };
}
```

### 5.2 async disposer 并发卸载

现状 `ExecutePluginUndoChain` 是同步 `Action` 逆序串行(`PluginManager.cs:362-374`)。升级为 `IAsyncDisposable` + 并发调度(对齐 Cordis:多个 async disposer 并发,顺序敏感的放单个 `ctx.effect` 内串行 await)。

```csharp
// infrastructure/Infrastructure/Plugins/Services/PluginManager.cs 新增
private readonly ConcurrentDictionary<string, List<IAsyncDisposable>> _pluginAsyncUndoChain = new();

/// <summary>异步逆序卸载 — 顺序敏感的 disposer 串行,独立的并发</summary>
private async Task ExecutePluginAsyncUndoChainAsync(string pluginName, CancellationToken ct)
{
    if (!_pluginAsyncUndoChain.TryRemove(pluginName, out var chain)) return;

    // 按注册逆序分组:同一 EffectGroup 内串行,不同组并发
    // 简化版:全部逆序串行 await(若需并发,按 group 分区 Task.WhenAll)
    for (int i = chain.Count - 1; i >= 0; i--)
    {
        try { await chain[i].DisposeAsync().ConfigureAwait(false); }
        catch (Exception ex) { _logger?.LogWarning(ex, "插件 {Plugin} async 撤销第 {Index} 项失败", pluginName, i); }
    }
}
```

```csharp
// PluginContext 新增 async effect
public void Effect(Func<IAsyncDisposable> factory)
{

public void Effect(Func<IDisposable> factory)
{
    var disposable = factory();
    _asyncUndoChain.Add(AsyncDisposableWrapper.From(disposable));
}

private sealed class AsyncDisposableWrapper : IAsyncDisposable
{
    private readonly IDisposable _inner;
    private AsyncDisposableWrapper(IDisposable inner) => _inner = inner;
    public static AsyncDisposableWrapper From(IDisposable d) => new(d);
    public ValueTask DisposeAsync()
    {
        _inner.Dispose();
        return ValueTask.CompletedTask;
    }
}
```

## 2. P0 紧急 — vendor/protocol 硬编码 if-else 链消除

### 2.1 目标

将 `EnvOverrideApplier` 和 `ConfigLoader` 中的 if-else 链改为 `FrozenDictionary<string, VendorKind>` 查表,符合:
- **状态机查表思想**(选型3): 输入字符串 → 查表 → 输出枚举,而非 if-else 链
- **枚举是唯一数据源**(AGENTS.md): 字符串值由 `[EnumValue]` 定义一次
- **AOT 友好**: `FrozenDictionary` 零分配 O(1) 查找

### 2.2 改动文件

| 文件 | 改动 |
|------|------|
| `core/safety/Guard/src/Configuration/Configuration2/Core/Mapping/EnvOverrideApplier.cs` | `InferProtocol`/`InferApiKeyEnvVar` 改为查表 |
| `core/safety/Guard/src/Configuration/Configuration2/Core/Loading/ConfigLoader.cs` | 行 226-236 if-else 链改为查表 |

### 2.3 设计方案

**新增静态查找表**(放在 `EnvOverrideApplier` 同文件或 `VendorKindExtensions` 中):

```csharp
// AOT 友好的不可变查找表 — OrdinalIgnoreCase 比较器
private static readonly FrozenDictionary<string, VendorKind> VendorByName =
    FrozenDictionary.Create(
        StringComparer.OrdinalIgnoreCase,
        new KeyValuePair<string, VendorKind>[]
        {
            new(VendorKind.OpenAi.ToValue(), VendorKind.OpenAi),
            new(VendorKind.Anthropic.ToValue(), VendorKind.Anthropic),
            new(VendorKind.Azure.ToValue(), VendorKind.Azure),
            new(VendorKind.DeepSeek.ToValue(), VendorKind.DeepSeek),
            new(VendorKind.Agnes.ToValue(), VendorKind.Agnes),
            new(VendorKind.Sensenova.ToValue(), VendorKind.Sensenova),
            new(VendorKind.Bedrock.ToValue(), VendorKind.Bedrock),
        });

// vendor → 协议推断表(替代 InferProtocol 的 if-else)
private static readonly FrozenDictionary<string, ProtocolKind> ProtocolByVendor =
    FrozenDictionary.Create(
        StringComparer.OrdinalIgnoreCase,
        new KeyValuePair<string, ProtocolKind>[]
        {
            new(VendorKind.Anthropic.ToValue(), ProtocolKind.Anthropic),
            new(VendorKind.Azure.ToValue(), ProtocolKind.Azure),
            // 其余 vendor 走 OpenAiCompatible 默认
        });
```

**查表替代 if-else**:

```csharp
// 改前
private static string? InferProtocol(string? vendor)
{
    if (string.IsNullOrEmpty(vendor)) return null;
    if (string.Equals(vendor, "anthropic", StringComparison.OrdinalIgnoreCase))
        return ProtocolKind.Anthropic.ToValue();
    if (string.Equals(vendor, "azure", StringComparison.OrdinalIgnoreCase))
        return ProtocolKind.Azure.ToValue();
    return ProtocolKind.OpenAiCompatible.ToValue();
}

// 改后(查表 + 默认值)
private static string? InferProtocol(string? vendor)
{
    if (string.IsNullOrEmpty(vendor)) return null;
    return ProtocolByVendor.TryGetValue(vendor, out var protocol)
        ? protocol.ToValue()
        : ProtocolKind.OpenAiCompatible.ToValue();
}
```

## 3. P1 高 — ProviderDefinition 中 "openai" 硬编码消除

### 3.1 目标

`AzureProviderDefinition` 中 9 处 `"openai"` 硬编码应改为 `VendorKind.OpenAi.ToValue()`,原因:
- Azure 复用 OpenAI 模型配置,但 `"openai"` 字符串重复硬编码 9 次
- 若 `VendorKind.OpenAi` 的 `[EnumValue]` 改值,这 9 处不会同步

### 3.2 改动文件

| 文件 | 改动 |
|------|------|
| `AzureProviderDefinition.cs` | 9 处 `"openai"` → `VendorKind.OpenAi.ToValue()`(或提取为 `private const string OpenAiVendor = ...`,但 const 不能用 ToValue(),故改为 `static readonly` 或内联) |
| `AnthropicCompatibleProviderDefinition.cs:36,58` | `"anthropic"` → `VendorKind.Anthropic.ToValue()` |
| `ContextWindowResolver.cs:70` | `"openai"` 兜底 → `VendorKind.OpenAi.ToValue()` |

### 3.3 设计权衡

**问题**: `const string` 不能用 `VendorKind.OpenAi.ToValue()`(ToValue 是运行时方法)。

**方案A**(推荐): 内联 `VendorKind.OpenAi.ToValue()`,JIT 内联后等效 const
**方案B**: `static readonly string OpenAiVendor = VendorKind.OpenAi.ToValue();` — 但 AOT 下需确认初始化顺序
**方案C**: 直接用 `VendorKindConstants.OpenAi`(源码生成器生成的 const 常量) — **最优,AOT 友好且编译期常量**

**采用方案C**: 确认 `EnumMetadataGenerator` 是否生成 `VendorKindConstants` 类(含 `public const string OpenAi = "openai";`)。若已生成,直接用常量;若未生成,先增强生成器。

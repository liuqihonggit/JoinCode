# 0164. 轮次闸门状态机 — 四类出口 + 强制验证边 + 计数熔断 + 推荐/申诉

- 状态：accepted（已实现 TASK132，含真机 exe 验收 2026-11-24）
- 日期：2026-11-24
- 决策者：项目架构组
- 替代：[0159](0159-round-gate-turn-termination.md) 的 5 选项集与收尾裁决（0159 的"收尾点强制 / 规则单源 / 作用域"结论继续有效，状态已置 superseded by 本文）
- 不做兼容：旧编号语义（3 规划任务 / 4 验收 / 5 结束）与旧文字别名一律删除，只认 0~11 编号与 `[EnumValue]` 规范值

## 背景

ADR 0159 的闸门只有 5 个选项（1 直接继续 / 2 TODO 继续 / 3 规划任务 / 4 验收 / 5 结束），
结构上只有"往前推"和"退出"两类走向：

- 卡死、方向错、做不完时没有合法出口，模型只能硬编或摆烂后强行选 5；
- 5 结束没有"完成终验"约束，模型自判"差不多"就能收尾；
- 全部选项平铺，模型每轮重选，抖动大；
- 没有计数器与熔断，返工/重规划可以无限循环。

## 决策

1. **选项集扩为 12 个（含隐式出口），分四类 + 挂起 + 出口**：
   - 执行 `1 直接继续 / 2 TODO 继续`
   - 验证 `3 自验 / 4 用户验收`
   - 元操作 `7 重新规划 / 8 回退修正`
   - 收敛 `9 降级交付 / 10 求助升级 / 11 放弃（失败终止）`
   - 挂起 `6 等候后台`
   - 出口 `5 完成` + 隐式 `0 阻塞上报`
   编号即 `choice` 参数，`0` 为隐式出口（缺用户输入），不参与 1~11 编号区。
2. **强制验证边**：执行类（1/2/8）会作废已有自验；`5 完成` 必须已在本会话拿到 `3 + verdict=pass`，
   否则运行时拦截并回灌"先自验"的阻断消息（堵死"产出没验证就宣布完成"）。
3. **新增 `RoundGateSession` 状态机**（与 `RoundGatePolicy` 同目录）承载：计数器、推荐表、熔断、终验裁决。
   QueryEngine 只持有实例并调用，禁止在循环里另写判定（延续 0159 规则单源）。
4. **计数熔断**（阈值常量集中在 `RoundGateSession`）：重规划 >2 → 强制 10；同一缺陷返工 >2 → 强制 7；
   自验连续 3 轮不通过 → 强制 10；连续 2 轮空转 → 强制 7；用户验收连续 2 次驳回 → 强制 7。
   熔断为**粘性**：只有改选强制项才解除，不能"换个证据"绕过。
5. **推荐 + 申诉替代平铺**：闸门每轮给"1 推荐 + 2 备选"，并把推荐/偏差/熔断并入工具结果；
   推荐按**本次选择生效后**的状态计算（否则注入的"下一轮推荐"滞后一格），偏离判定则对比"本次选择前"的推荐；
   连续偏离 2 次后 `AppealLocked`，提示必须按推荐路径执行。
6. **证据护栏按需注入**：`round_gate` 新增 `evidence` / `subject` / `verdict` 参数。无证据的执行/元操作轮累计空转；
   三问护栏文本**只在本轮未提交 `evidence` 时**注入（有证据就不再重复说教），不做每轮常驻。
7. **模式开关**：`JCC_ROUND_GATE_STRICT=1` 时 `5 完成` 与 `9 降级交付` 必须已移交 `4 用户验收`（严格模式）。
8. **提示词按需注入，不预载全量**：系统 Section 只保留协议骨架与硬约束（哪些能收尾、验证边、熔断、申诉），
   具体选项提示词由 `round_gate` 工具结果**按所选那一项注入**；`choice` 映射只在工具描述里以一行摘要出现。
   报错的闸门调用（参数非法）不推进状态机，避免把"参数写错"误记成一次失败自验。
9. **新增 `11 放弃（失败终止）`**（TASK133）：与 `9 降级`（交付可用子集）和 `10 求助`（等外部输入后继续）不同，
   本项表示不再继续投入。**必须有失败依据**（本会话至少一次 `3 verdict=fail`，累计不随返工清零），
   且工具层强制 `note` 写失败报告（失败证据/已试路径/根因类别/残留影响/可续做建议）；
   严格模式下还需先 `4` 移交。放弃后下一轮推荐 `0 阻塞上报`，不再推荐"继续"。
10. **`5 完成` 绑定交付流程**（TASK133）：完成提示词要求"提交 → push 功能分支 → 创建 PR（目标 main、auto-merge）"；
   若缺 git 凭证 / 无 push 权限 / 无 remote，则**放弃创建 PR**，在总结里报告"未创建 PR + 原因 + 已完成到哪一步"，
   禁止反复重试或改走其它通道。

## 考虑过的替代方案

| 方案 | 放弃原因 |
|------|----------|
| 保留 5 选项，只加"完成需自验"一条 | 卡死/做不完仍无合法出口，模型只能硬编或摆烂（用户提案的核心诉求未解决） |
| 把状态机实现在 `RoundGateToolHandlers`（工具内自持状态） | 工具处理器无会话标识，多会话/子代理并发下状态会串；状态必须跟单次查询生命周期 |
| 每次工具调用都强制过闸门 | token/延迟成本高；收尾点强制 + 三问护栏已覆盖"假进展" |
| 系统 Section 常驻 11 条选项提示词 | 每轮都付全量 token，且模型没有"选完才看细节"的锚点；改为 Section 放骨架、工具结果按需注入所选项 |
| 把 11 项拆成 11 个工具 | 用户明确否决：单工具 + `choice` 参数才是对的，拆成多入口会让工具表膨胀且难以统一裁决 |
| 报错调用也记一次选择 | 参数写错会被当成"失败自验/偏离推荐"，把计数推向熔断；改为只有成功调用才推进状态机 |
| 让闸门阻塞等待用户验收 | 与 ADR 0159 的"AI 自选、不阻塞、无人值守可用"冲突；改为 4 移交 ○ 清单后收尾 |

## 后果

- 正面：早退有验证链拦截；卡死/返工/做不完有合法出口；死循环由计数熔断兜住；模型每轮拿到明确推荐，减少抖动。
- 代价：模型需多调用一次 3 自验才能选 5；选项语义（`choice` 编号表）仍需在工具描述里占一行。
- 提示词成本：常驻部分只有 Section 骨架（约 10 行）+ 工具描述一行选项表；选项细则按需注入，不随轮次重复。
- 边界：`0 阻塞上报` 与 `4 用户验收` 属于"把回合交给用户"，无人值守会话下会以出口形式停下；
  真正无人值守长任务应把 `JCC_ROUND_GATE=off` 或依赖闸门推荐持续推进。
- 遗留：推荐表、熔断阈值目前是常量，后续如需要再加环境变量覆盖（`JCC_ROUND_GATE_MAX_REJECT` 已可配拦截上限）。

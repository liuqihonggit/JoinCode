# 0164. 轮次闸门状态机 — 四类出口 + 强制验证边 + 计数熔断 + 推荐/申诉

- 状态：accepted（已实现 TASK132，含真机 exe 验收 2026-11-24）
- 日期：2026-11-24
- 决策者：项目架构组
- 替代：[]（对 [0159](0159-round-gate-turn-termination.md) 的选项集与裁决逻辑做扩展，0159 的"闸门只在收尾点强制 / 规则单源 / 作用域"结论继续有效）

## 背景

ADR 0159 的闸门只有 5 个选项（1 直接继续 / 2 TODO 继续 / 3 规划任务 / 4 验收 / 5 结束），
结构上只有"往前推"和"退出"两类走向：

- 卡死、方向错、做不完时没有合法出口，模型只能硬编或摆烂后强行选 5；
- 5 结束没有"完成终验"约束，模型自判"差不多"就能收尾；
- 全部选项平铺，模型每轮重选，抖动大；
- 没有计数器与熔断，返工/重规划可以无限循环。

## 决策

1. **选项集扩为 11 个（含隐式出口），分四类 + 挂起 + 出口**：
   - 执行 `1 直接继续 / 2 TODO 继续`
   - 验证 `3 自验 / 4 用户验收`
   - 元操作 `7 重新规划 / 8 回退修正`
   - 收敛 `9 降级交付 / 10 求助升级`
   - 挂起 `6 等候后台`
   - 出口 `5 完成` + 隐式 `0 阻塞上报`
   编号即 `choice` 参数，`0` 为隐式出口（缺用户输入），不参与 1~10 编号区。
2. **强制验证边**：执行类（1/2/8）会作废已有自验；`5 完成` 必须已在本会话拿到 `3 + verdict=pass`，
   否则运行时拦截并回灌"先自验"的阻断消息（堵死"产出没验证就宣布完成"）。
3. **新增 `RoundGateSession` 状态机**（与 `RoundGatePolicy` 同目录）承载：计数器、推荐表、熔断、终验裁决。
   QueryEngine 只持有实例并调用，禁止在循环里另写判定（延续 0159 规则单源）。
4. **计数熔断**（阈值常量集中在 `RoundGateSession`）：重规划 >2 → 强制 10；同一缺陷返工 >2 → 强制 7；
   自验连续 3 轮不通过 → 强制 10；连续 2 轮空转 → 强制 7；用户验收连续 2 次驳回 → 强制 7。
   熔断为**粘性**：只有改选强制项才解除，不能"换个证据"绕过。
5. **推荐 + 申诉替代平铺**：闸门每轮给"1 推荐 + 2 备选"，并把推荐/偏差/熔断并入工具结果；
   连续偏离 2 次后 `AppealLocked`，提示必须按推荐路径执行。
6. **证据护栏**：`round_gate` 新增 `evidence` / `subject` / `verdict` 参数。无证据的执行/元操作轮累计空转；
   三问护栏文本随每次调用注入。
7. **模式开关**：`JCC_ROUND_GATE_STRICT=1` 时 `5 完成` 与 `9 降级交付` 必须已移交 `4 用户验收`（严格模式）。

## 考虑过的替代方案

| 方案 | 放弃原因 |
|------|----------|
| 保留 5 选项，只加"完成需自验"一条 | 卡死/做不完仍无合法出口，模型只能硬编或摆烂（用户提案的核心诉求未解决） |
| 把状态机实现在 `RoundGateToolHandlers`（工具内自持状态） | 工具处理器无会话标识，多会话/子代理并发下状态会串；状态必须跟单次查询生命周期 |
| 每次工具调用都强制过闸门 | token/延迟成本高；收尾点强制 + 三问护栏已覆盖"假进展" |
| 让闸门阻塞等待用户验收 | 与 ADR 0159 的"AI 自选、不阻塞、无人值守可用"冲突；改为 4 移交 ○ 清单后收尾 |

## 后果

- 正面：早退有验证链拦截；卡死/返工/做不完有合法出口；死循环由计数熔断兜住；模型每轮拿到明确推荐，减少抖动。
- 代价：选项与提示词体积变大（系统 Section 与工具描述都变长）；模型需多调用一次 3 自验才能选 5。
- 边界：`0 阻塞上报` 与 `4 用户验收` 属于"把回合交给用户"，无人值守会话下会以出口形式停下；
  真正无人值守长任务应把 `JCC_ROUND_GATE=off` 或依赖闸门推荐持续推进。
- 遗留：推荐表、熔断阈值目前是常量，后续如需要再加环境变量覆盖（`JCC_ROUND_GATE_MAX_REJECT` 已可配拦截上限）。

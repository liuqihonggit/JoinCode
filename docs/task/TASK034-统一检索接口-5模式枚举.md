# TASK034: 统一检索接口 — 单一 MCP 工具

> 状态: 设计中
> 创建: 2026-10-03
> 关联: 无（不写 ADR，用户明确要求）

## 1. 背景与动机

### 1.1 问题

当前代码检索分散在 **58 个 MCP 工具**中，职责重叠、接口不一致。Explore agent 发现 **10 个功能重叠群**：

| 重叠群 | 工具 | 问题 |
|--------|------|------|
| 符号搜索 | `code_index_search` / `code_index_search_comprehensive` / `code_index_find_definition` / `lsp_workspace_symbol` / `symbol_search` | 5 个入口重叠 |
| 查找引用 | `code_index_find_references` / `lsp_find_references` / `code_index_get_callers` | 3 个入口重叠 |
| 调用方/被调用方 | `code_index_get_callers`/`callees` / `lsp_incoming`/`outgoing_calls` / `graph_explain` | 3 个入口重叠 |
| 定义跳转 | `code_index_find_definition` / `lsp_goto_definition`/`implementation` | 2 个入口重叠 |
| 调用链/路径 | `code_index_get_call_chain` / `graph_path` | 2 个入口重叠 |
| 影响分析 | `code_index_get_impact_scope` / `code_index_get_affected_files` / `graph_analyze_change_impact` | 3 个入口重叠 |
| 项目依赖 | `code_index_get_project_deps`/`dependents`/`affected` / `graph_analyze_change_impact` | 2 个入口重叠 |
| 语义搜索 | `code_index_search_semantic` / `HybridQueryRouter`（已实现但**未接入**） | 2 个入口重叠 |
| 文本搜索 | `grep` / `search_code` / `search_text` / `search_codebase` / `code_search` / `symbol_search` | 6 个工具实现**完全相同**（都复用 ripgrep） |
| 图查询 | `graph_query` / `code_index_explore` | 2 个入口重叠 |

**核心 bug**：全量构建用 `LineBasedChunkExtractor`（500行/块，Kind=Document），增量更新用 `CollectChunksWithParents`（AST符号切块，Kind=真实类型）。两者不一致导致 `symbol_kind` 过滤在全量构建后返回空。

**HybridQueryRouter 已实现但未被 MCP 工具调用** — `code_index_search_semantic` 直接绕过它。

### 1.2 目标

统一成**单一 MCP 工具** `code_query`，用 `SearchMode` 枚举区分 6 种模式，**默认混合召回**。不要任何向后兼容。删除所有被取代的旧工具。

## 2. 六种检索模式

### 2.1 模式定义

```csharp
public enum SearchMode {
    [EnumValue("hybrid")]    Hybrid,     // 混合召回（默认）— 符号+向量+图谱+文档并行，去重合并
    [EnumValue("symbol")]    Symbol,     // 单纯符号检索 — Token AND-OR 匹配 AST 符号
    [EnumValue("vector")]    Vector,     // 单纯向量检索 — ONNX 语义嵌入 + 余弦相似度
    [EnumValue("graph")]     Graph,      // 代码图谱关系 — 调用方/被调用方/引用/依赖/路径/子图
    [EnumValue("document")]  Document,   // 文档检索 — .md 文件语义搜索
    [EnumValue("project")]   Project     // 项目关系 — 依赖/被依赖/受影响/NuGet
}
```

### 2.2 各模式行为

| 模式 | 数据源 | 查询类型 | 返回 |
|------|--------|----------|------|
| `hybrid` | 符号索引+向量索引+图谱+文档 | 自然语言或符号名 | 合并去重结果 + 图谱关系 |
| `symbol` | SymbolSearcher（Token AND-OR） | 符号名/glob | 匹配符号列表 |
| `vector` | EmbeddingIndex（ONNX嵌入） | 自然语言或代码片段 | 语义相似块列表 |
| `graph` | CallGraph + DependencyGraph | 符号FQN + graph_relation | 调用方/被调用方/引用/依赖/路径/子图/定义/继承者 |
| `document` | EmbeddingIndex（file_type=md过滤） | 自然语言 | 匹配文档块列表 |
| `project` | ProjectDependencyGraph | 项目路径 + project_relation | 依赖/被依赖/受影响/NuGet/全部 |

### 2.3 混合召回策略（Hybrid）

```
输入: query, top_k, filters...
  ├── 并行 ──┐
  │          ├── Symbol:  SymbolSearcher.SearchAsync(query) → top_k 个符号
  │          ├── Vector:  EmbeddingIndex.SearchAsync(query) → top_k 个语义块
  │          └── Document: EmbeddingIndex.SearchAsync(query, file_type=md) → top_k 个文档块
  ├── 合并:   按 FilePath+StartLine 去重
  ├── 图谱:   对每个结果展开 1 跳图谱关系（调用方/被调用方）
  └── 排序:   按相关度分数降序
输出: top_k 个结果 + 图谱关系
```

## 3. 统一接口设计

### 3.1 工具定义

```
code_query(
    query: string,               // 查询（自然语言或符号名/正则）
    mode: SearchMode = hybrid,   // 检索模式（默认混合召回）
    top_k: int = 10,             // 最大结果数
    // --- 过滤参数 ---
    symbol_kind: string? = null,     // 符号类型过滤（class/method/constructor/...）
    file_type: string? = null,       // 文件类型过滤（cs/md/...）
    namespace_filter: string? = null,  // 命名空间过滤
    // --- 内容控制 ---
    include_source_text: bool = false,    // 包含块原文
    include_parent_document: bool = false,  // 包含父文档
    include_graph: bool = true,     // 包含图谱关系
    // --- 图谱参数（mode=graph） ---
    graph_relation: string? = null,  // 关系类型（见 3.2）
    graph_depth: int = 1,           // 展开深度（0=不展开，1=1跳，2=2跳）
    from_symbol: string? = null,    // 调用链/路径起点
    to_symbol: string? = null,      // 调用链/路径终点
    // --- 项目参数（mode=project） ---
    project_relation: string? = null,  // 项目关系类型（见 3.3）
    // --- 其他 ---
    persist_dir: string? = null     // 持久化目录
)
```

### 3.2 graph_relation 枚举值（mode=graph）

| graph_relation | 取代旧工具 | 功能 |
|----------------|-----------|------|
| `callers` | `code_index_get_callers` | 调用方 |
| `callees` | `code_index_get_callees` | 被调用方 |
| `references` | `code_index_find_references` | 所有引用 |
| `definition` | `code_index_find_definition` | 定义位置 |
| `call_chain` | `code_index_get_call_chain` | 调用链（需 from_symbol + to_symbol） |
| `path` | `graph_path` | 最短路径（需 from_symbol + to_symbol） |
| `impact_scope` | `code_index_get_impact_scope` | 影响范围 |
| `inheritors` | `code_index_get_inheritors` | 继承者 |
| `dependencies` | `code_index_get_dependencies` | 依赖 |
| `affected_files` | `code_index_get_affected_files` | 受影响文件 |
| `subgraph` | `graph_extract_subgraph` | 子图提取 |
| `explain` | `graph_explain` | 符号解释（聚合 callers+callees+社区+同文件） |
| `all`（默认） | `graph_query` + `code_index_explore` | 自动选择 |

### 3.3 project_relation 枚举值（mode=project）

| project_relation | 取代旧工具 | 功能 |
|------------------|-----------|------|
| `deps` | `code_index_get_project_deps` | 项目依赖 |

## 4. symbol_kind 过滤修复（方案 C+）

### 4.1 问题

`LineBasedChunkExtractor` 所有块 `Kind = SymbolKind.Document`，`symbol_kind=constructor` 过滤返回空。

### 4.2 方案

给 `ChunkMetadata` 加 `ContainedSymbolKinds` (int BitMask) 字段，记录块内包含的所有符号类型。`MatchesSymbolKind` 检查 BitMask 是否包含过滤值。

### 4.3 改动清单

| 文件 | 改动 |
|------|------|
| `ChunkInfo.cs` | 加 `ContainedSymbolKinds` (int) 字段 |
| `ChunkMetadata.cs` | 加 `ContainedSymbolKinds` (int) 字段 |
| `LineBasedChunkExtractor.cs` | 遍历 symbols 时用 `BitMask.Of()` 计算 BitMask |
| `EmbeddingIndex.cs` | `IndexChunksAsync` 设置 BitMask + `MatchesSymbolKind` 检查 BitMask |
| `LsmEmbeddingPersistence.cs` | `SerializeMeta`/`DeserializeMeta` 加一个 int 字段 |

### 4.4 代价

- 持久化格式变更，需重建索引（10s）
- 构建速度不变（仍用 `LineBasedChunkExtractor`）

## 8. 设计决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 切块方式 | 保持 `LineBasedChunkExtractor` | AST 切块构建要半小时，固定行数切块 10s |
| symbol_kind 过滤 | `ContainedSymbolKinds` BitMask | 零成本（遍历 symbols 时顺便算），不改切块方式 |
| 统一工具名 | `code_query` | 单一 MCP，用户明确要求 |
| 默认模式 | `hybrid` | 用户明确要求"优先混合召回" |
| 向后兼容 | 不要 | 用户明确要求"不要任何兼容" |
| 旧工具处理 | 删除 28 个 | 不保留兼容，减少维护负担 |
| LSP 保留独立 | 是 | 不同引擎（OmniSharp 实时 vs AST 索引），合并无意义 |
| grep 保留独立 | 是 | 不同引擎（ripgrep vs AST/向量索引），合并无意义 |
| 图分析保留独立 | 是 | 算法分析（标签传播/DAG/度排序），不是检索 |
| HybridQueryRouter | 接入或删除 | 已实现但未接入，要么接入到 mode=hybrid，要么删除 |

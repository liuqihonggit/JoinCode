# 文件工具统一安全防御改造

## 背景

`FileToolHandlers.Edit.cs` 内有 5 个写入/编辑类工具方法，但只有 `FileEditAsync` 有完整安全防御，其余 4 个（`FileEditRegex`/`FileInsertLines`/`FileDeleteLines`/`FileBatchEdit`）缺失。`FileToolHandlers.Patch.cs` 的 `FileApplyPatch` 同样缺失。写入和编辑可能引入团队密钥，必须统一防御。

## 现状分析

|------|-----|------|--------|------|------|---------|

| `FileEditAsync` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

## 改造方案

### 1. 提取统一写入前安全防御方法 `ValidateWriteSafetyAsync`

在 `FileToolHandlers.cs` 中新增，封装 5 层防御链：
1. UNC 路径拒绝（防凭据泄露）
2. 沙箱路径解析
3. 团队密钥检测（拒绝写入团队记忆文件中的密钥）
4. 写前读校验 + 脏写保护（Stale-write guard）
5. 写前备份

返回 `WriteSafetyContext` record：包含沙箱解析后路径 + 拒绝结果（null=通过）。

### 2. 提取统一写入后通知方法 `NotifyWriteComplete`

在 `FileToolHandlers.cs` 中新增，封装 4 步通知：
1. 清除已投递 LSP 诊断
2. 通知 LSP 服务器文件变更（fire-and-forget）
3. 记录遥测
4. 通知文件写入监听器

### 3. 改造 5 个缺失防御的工具

每个工具在执行 I/O 前调用 `ValidateWriteSafetyAsync`，成功后调用 `NotifyWriteComplete`。

### 4. 改造 FileWriteAsync 和 FileEditAsync 复用统一方法

消除重复代码，统一走 `ValidateWriteSafetyAsync` + `NotifyWriteComplete`。
注意：`FileEditAsync` 有额外的 settings/keyword/doctor/ipynb 校验，这些保留在工具方法内（非通用防御）。

## 手动测试（参考 ADR 0080）

### 测试工具列表

| 工具 | 测试要点 |
|------|----------|
| `file_write` | 正常写入、UNC 拒绝、密钥拒绝、写前读拒绝 |
| `file_edit` | 正常编辑、密钥拒绝、settings 校验 |
| `file_edit_regex` | 正则编辑、密钥拒绝（新增）、写前读（新增） |
| `file_insert_lines` | 插入行、密钥拒绝（新增）、写前读（新增） |
| `file_delete_lines` | 删除行、写前读（新增） |
| `file_batch_edit` | 批量编辑、密钥拒绝（新增） |
| `file_apply_patch` | 应用补丁、密钥拒绝（新增） |

### 验收标准

- 编译通过（Debug）
- 所有工具正常路径返回成功
- 密钥防御：写入含密钥内容时返回 `TeamMemSecretRejected`
- UNC 防御：UNC 路径返回 `UncPathWriteRejected`
- 写前读：未读先写返回 `FileNotReadBeforeWrite`

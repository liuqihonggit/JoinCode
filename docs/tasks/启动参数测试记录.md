## 问题#10 详情: `2>nul` 意外创建文件

**场景**: 执行 `where jcc 2>nul` 时,在 bash 环境中 `2>nul` 不会重定向到 Windows NUL 设备,而是创建了一个名为 `nul` 的普通文件(54 字节,内容为 stderr 输出)。

**根因**: `2>nul` 是 Windows CMD/PowerShell 的语法,在 bash 中 `nul` 被当作普通文件名而非特殊设备名。bash 正确的空设备重定向是 `2>/dev/null`。

**影响**: 
- 意外向工作目录写入垃圾文件
- 可能污染 git status(显示为未跟踪文件)
- 可能被后续命令误读或误操作

**正确做法**:
- bash 中用 `2>/dev/null` 抑制 stderr
- PowerShell 中用 `2>$null` 抑制 stderr
- CMD 中用 `2>nul` 抑制 stderr(仅限 CMD)

**拦截方案**: 待定 — 需在命令执行层检测 `2>nul` 模式并警告/阻止/自动替换

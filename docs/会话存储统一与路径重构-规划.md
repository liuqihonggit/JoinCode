# 会话存储统一与路径重构规划

> 创建: 2026-08-22
> 起因: `--continue`/`--resume` 因 .jsonl vs .json 格式不一致而失效,CLI 产生的会话历史无法跨进程恢复,导致多轮测试(E2E + 手动)历史丢失。

## 一、问题背景

### 1.1 现象
- CLI 每轮对话写入 `~/.jcc/sessions/{id}.jsonl`(JSONL, `TranscriptService`)
- `--continue`/`--resume` 只读 `~/.jcc/sessions/{id}.json`(JSON 快照, `SessionData`)
- **无桥接转换** → CLI 会话无法被 `--continue` 恢复 → 跨进程多轮测试历史丢失

### 1.2 根因
两套并行存储机制,格式与读写方互不相通:

| 维度 | .jsonl (TranscriptService) | .json (SessionData) |
|------|---------------------------|---------------------|
| 写入方 | `CliSession.AppendTranscriptEntriesAsync`(CLI 主路径) | `ResumeCommand.SaveSessionAsync` / GUI / RenameCommand |
| 读取方 | `ListTranscriptsAsync` / `LoadTranscriptAsync` | `SessionResumeStep` / `ResumeCommand` / GUI |
| 格式 | append-only JSONL | 整存整取 JSON |
| 字段 | `TranscriptEntry`(丰富: Role/Content/Timestamp/ModelId/Tokens/AgentId/ToolName/Type/CustomTitle...) | `SessionData{Id,ProjectPath,CustomTitle,CreatedAt,Messages:List<SessionMessage>}` |

### 1.3 路径不完备
现状为**扁平结构**,仅 subagents 用了子目录:
```
~/.jcc/sessions/
  ├── {id}.jsonl              ← 主 transcript (扁平)
  ├── {id}.json               ← SessionData 快照 (扁平)
  └── {id}/                   ← 仅 AgentTranscriptService
      └── subagents/
          ├── agent-{agentId}.jsonl
          └── agent-{agentId}.meta.json
```

## 二、目标架构

### 2.1 统一到 .jsonl + 每会话一文件夹
```
~/.jcc/sessions/
  └── {id}/
      ├── transcript.jsonl    ← 主聊天历史 (统一格式, append-only)
      ├── meta.json           ← 会话元数据 (id, projectPath, customTitle, createdAt)
      └── subagents/          ← 子代理 (位置不变)
          ├── agent-{agentId}.jsonl
          └── agent-{agentId}.meta.json
```

### 2.2 设计决策
- **统一用 .jsonl**:append-only 性能好(每轮追加,无需重写整个文件);`TranscriptEntry` 字段丰富;CLI 主路径已用它,改动最小
- **每会话一文件夹**:隔离会话内产物(transcript/meta/subagents/costs...),便于清理、权限管控、未来扩展
- **meta.json 替代 SessionData**:仅存元数据(Id/ProjectPath/CustomTitle/CreatedAt),消息历史全在 transcript.jsonl
- **CustomTitle 通过 transcript entry(Type="custom-title")存储**(TranscriptService.SaveCustomTitleAsync 已实现),meta.json 可缓存最新 title 供快速列表

### 2.3 统一入口(本次重构核心)

**问题**:现状写入方 4 处各写各的,读取方 4 处各自拼路径,导致格式分叉、路径逻辑重复:

| 调用方 | 现状 | 问题 |
|--------|------|------|
| `CliSession.AppendTranscriptEntriesAsync` | 调 `TranscriptService.AppendEntriesAsync` 写 .jsonl | ✅ 已走统一入口 |
| `ResumeCommand.SaveSessionAsync`(static) | 直接 `IFileSystem` 写 .json | ❌ 绕过 TranscriptService |
| `RenameCommand` | 混用:拿 ITranscriptService + 直读 .json | ❌ 半迁移 |
| `GuiSessionStore` | 直接 `IFileSystem` 读写 .json | ❌ 绕过 TranscriptService |
| `SessionResumeStep`(static) | 直接 `IFileSystem` 读 .json | ❌ 绕过 TranscriptService |

**方案**:以 `ITranscriptService` 为会话存储**唯一入口**,补齐缺失能力,所有读写收敛到它:

```
ITranscriptService (唯一入口, 已有 + 新增)
  已有:
    AppendEntryAsync / AppendEntriesAsync     // 追加历史 → {id}/transcript.jsonl
    LoadTranscriptAsync                       // 读历史
    ListTranscriptsAsync                      // 列表(扫子目录)
    DeleteTranscriptAsync / TranscriptExistsAsync
    SaveCustomTitleAsync / GetCustomTitleAsync
    InsertContentReplacementAsync / LoadContentReplacementsAsync
  新增:
    SaveMetaAsync(sessionId, SessionMeta)     // → {id}/meta.json
    GetMetaAsync(sessionId) → SessionMeta?    // ← {id}/meta.json
```

**新增类型**:
```csharp
public sealed record SessionMeta
{
    public string Id { get; init; } = string.Empty;
    public string ProjectPath { get; init; } = string.Empty;
    public DateTime CreatedAt { get; init; }
}
```
(CustomTitle 不进 meta,已在 transcript entry 里;GetCustomTitleAsync 扫描获取)

**收敛后路径逻辑只在 `TranscriptService` 内部**:
- `GetTranscriptPath(id)` → `sessions/{id}/transcript.jsonl`
- `GetMetaPath(id)` → `sessions/{id}/meta.json`
- `GetSubagentDir(id)` → `sessions/{id}/subagents/`(已存在)

**废弃**(移到 `.xxx/`):
- `ResumeCommand.SaveSessionAsync`(static 直写)
- `SessionData` / `SessionMessage` / `SessionLiteData`(被 TranscriptEntry + SessionMeta 取代)
- 所有调用方直接 `Path.Combine(SessionsPath, $"{id}.json")` 拼路径的代码

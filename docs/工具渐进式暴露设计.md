# 工具渐进式暴露设计

## 1. 目标

让 LLM 在**不破坏前缀缓存**的前提下，按需获取工具 schema，而非一次性加载全部工具定义。

- 首次请求：只暴露核心工具完整 schema + 所有工具名称（不含 schema）
- LLM 自行探索：通过 `tool_description_request` 按需加载 MCP/Slash 工具 schema
- OnError 强行注入：工具执行失败时，把修复工具的完整 schema 作为文本消息注入，LLM 无需自行探索即可调用

## 2. 三种 ToolKind 的暴露策略

| ToolKind | 首次请求位置 | 含 schema? | LLM 可直接调用? | 暴露机制 |
|----------|-------------|-----------|----------------|----------|
| **System** | `tools` 字段 | ✅ 完整 schema | ✅ 直接调用 | 始终暴露 |
| **Mcp / Slash** | `tool_groups` 字段 | ❌ 只有名称 | ❌ 需先获取 schema | 自行探索（两阶段加载） |
| **OnError** | `tool_groups` 字段 | ❌ 只有名称 | ❌ 需先获取 schema | 自行探索 **或** 失败时强行注入 |

### 核心原则

- **`tools` 字段固定不变** — 只含 System 工具，数量稳定 → 前缀缓存命中
- **`tool_groups` 拥有一切非 System 工具** — Mcp + Slash + OnError，只有名称列表 → 名称增减对前缀缓存影响极小
- **schema 按需加载** — LLM 用 `tool_description_request` 请求，或由 OnError 中间件强行注入

## 3. 两阶段加载流程（自行探索）

```
┌─────────────┐                        ┌──────────┐
│  LLM 首次   │  tools: [core_tools]   │          │
│  请求       │  tool_groups: [所有名称] │  Client  │
└─────────────┘ ─────────────────────► └──────────┘

┌─────────────┐                        ┌──────────┐
│  LLM 响应   │  tool_description_     │          │
│  (需要工具) │  request: ["tool_a"]   │  Client  │
└─────────────┘ ◄───────────────────── └──────────┘

┌─────────────┐                        ┌──────────┐
│  第二次请求 │  tool_descriptions:    │          │
│  (带 schema)│  [tool_a 完整 schema]  │  Client  │
└─────────────┘ ─────────────────────► └──────────┘

┌─────────────┐                        ┌──────────┐
│  LLM 响应   │  tool_call: tool_a(...) │          │
│  (调用工具) │                        │  Client  │
└─────────────┘ ◄───────────────────── └──────────┘
```

1. **首次请求**：`BuildToolsFromKernel` 把 `core_tools` 组工具放入 `tools`（完整 schema），`mcp_tools` 组工具放入 `tool_groups`（只有名称）
2. **LLM 响应 `tool_description_request`**：LLM 输出 `{"type":"tool_description_request","tools":["tool_a"]}` 请求 schema
3. **第二次请求**：`CreateSecondRequestWithDescriptions` 构建含 `tool_descriptions` 的请求
4. **LLM 调用工具**：收到 schema 后生成 `tool_call`

## 4. OnError 强行注入流程

```
┌─────────────┐                        ┌──────────┐
│  LLM 调用   │  tool_call: some_tool  │          │
│  某工具     │                        │  Client  │
└─────────────┘ ─────────────────────► └──────────┘
                                       工具执行失败!
                                       ┌──────────┐
                                       │ OnError  │
                                       │ Middleware│
                                       └──────────┘
                                       注入文本消息:
                                       "工具执行失败。
                                        以下修复工具可用:
                                        {完整 schema JSON}
                                        请选择合适的修复工具。"
┌─────────────┐                        ┌──────────┐
│  LLM 下一轮 │  收到注入的 schema     │          │
│  直接调用   │  tool_call: error_     │  Client  │
│  修复工具   │  recovery(...)         │          │
└─────────────┘ ◄───────────────────── └──────────┘
```

- OnError 工具在 `tool_groups` 中有名称 → LLM 知道存在
- 工具失败时，中间件把 OnError 工具的**完整 schema 作为文本**注入 → "从自行探索变成强行注入单个"
- LLM 收到 schema 后无需 `tool_description_request`，直接生成 `tool_call`

## 5. 当前问题

### 问题1：OnError 工具被完全过滤

`McpToolBridge.CreatePluginAsync`（`services/Mcp/src/Bridge/McpToolBridge.cs:22`）：

```csharp
var visibleHandlers = allTools.Values
    .Where(h => h.Kind != ToolKind.OnError)  // ← OnError 工具被过滤掉
    .ToList();
```

OnError 工具不出现在 `tools` 也不出现在 `tool_groups` → LLM 完全不知道有这些工具。

### 问题2：注入文本只有名称+描述，没有 schema

`OnErrorToolInjectionMiddleware`（`core/execution/McpToolDispatch/src/Core/Middleware/OnErrorToolInjectionMiddleware.cs:52-56`）：

```csharp
sb.AppendLine($"- {tool.Name}: {tool.Description}");  // ← 只有名称和描述
```

LLM 知道工具名但不知道参数格式 → 无法调用。

### 问题3：生成器也过滤 OnError

`McpToolDispatchGenerator`（`generators/McpToolDispatch.Generator/src/McpToolDispatchGenerator.cs:778`）：

```csharp
var filtered = kvp.Value.Where(t => t.Kind != ToolKind.OnError).ToList();  // ← GetVisibleToolCategories 也过滤
```

工具分类导航中看不到 OnError 工具。

## 6. 修改方案

### 修改1：McpToolBridge — 让 OnError 进入 tool_groups

`services/Mcp/src/Bridge/McpToolBridge.cs`

去掉 OnError 过滤，让 OnError 工具进入 `mcp_tools` 组（只有名称）：

```csharp
// 修改前
var visibleHandlers = allTools.Values
    .Where(h => h.Kind != ToolKind.OnError)
    .ToList();

// 修改后
var visibleHandlers = allTools.Values.ToList();
```

OnError 工具的 Kind 不是 System，会走 else 分支进入 `mcpFunctions` → `mcp_tools` 组 → 只有名称。

### 修改2：OnErrorToolInjectionMiddleware — 注入完整 schema

`core/execution/McpToolDispatch/src/Core/Middleware/OnErrorToolInjectionMiddleware.cs`

把注入内容从"名称+描述"改为"完整 schema JSON"：

```csharp
// 修改前
sb.AppendLine($"- {tool.Name}: {tool.Description}");

// 修改后 — 注入完整 schema，格式对齐 tool_descriptions
foreach (var tool in relevantTools.Values)
{
    var schemaJson = JsonSerializer.Serialize(new
    {
        type = "function",
        function = new
        {
            name = tool.Name,
            description = tool.Description,
            parameters = tool.InputSchema
        }
    }, JsonContext.Default);
    sb.AppendLine(schemaJson);
}
```

### 修改3：McpToolDispatchGenerator — GetVisibleToolCategories 同步

`generators/McpToolDispatch.Generator/src/McpToolDispatchGenerator.cs:778`

去掉 OnError 过滤，让工具分类导航也包含 OnError 工具：

```csharp
// 修改前
var filtered = kvp.Value.Where(t => t.Kind != ToolKind.OnError).ToList();

// 修改后
var filtered = kvp.Value.ToList();
```

## 7. 不变性

| 不变量 | 保证 |
|--------|------|
| `tools` 字段只含 System 工具 | `McpToolBridge` line 41: `if (h.Kind == ToolKind.System)` 才进 coreFunctions |
| `tool_groups` 含所有非 System 工具 | 去掉 OnError 过滤后，Mcp/Slash/OnError 都进 mcpFunctions |
| 前缀缓存命中 | `tools` 字段固定（System 工具不变），`tool_groups` 只是名称列表 |
| OnError 工具可执行 | `IToolRegistry` 中已注册，`ExecuteToolAsync` 按 name 查找，不依赖 `kernel.Plugins` |
